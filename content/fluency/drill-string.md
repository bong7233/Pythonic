# 11.9 드릴 I — 문자열·검증

::: lead
여기부터는 읽는 절이 아니다. 앞의 여덟 절에서 고른 무기를 **타이머를 켜고 휘두르는** 자리다. 문제 일곱 개가 있고, 각 문제마다 코드보다 먼저 나오는 것이 **"어떻게 생각하는가"** 다. 실전에서 갈리는 것은 `Counter` 를 아는가가 아니라, 지문의 어느 문장에서 손이 어느 도구로 가는가다. 새 지식은 하나도 없다 — 전부 [11.2](#/stdlib-arsenal)~[11.6](#/sorting-as-tool)에 있는 것이고, 여기서는 그것이 **손에 붙었는지**만 확인한다.
:::

## 이 드릴을 쓰는 법

규칙 셋. 어기면 훈련이 아니라 독서가 된다.

1. **문제 설명까지만 읽고 멈춘다.** 타이머를 켜고 편집기에서 직접 짜라. 예시 입출력이 전부 통과해야 끝이다.
2. **시간이 다 되면 못 풀어도 멈춘다.** 그리고 코드가 아니라 **"어떻게 생각하는가"** 를 먼저 읽어라. 대조할 것은 답이 아니라 **판단의 순서**다. 어디서 갈라졌는지 찾으면 그게 당신이 다음에 고칠 지점이다.
3. **통과했어도 `흔한 실수` 상자는 읽어라.** 예시 입력만 우연히 통과하는 코드가 실전에서 떨어진다.

막히면 [11.7 5단계 루틴](#/blank-page-routine)으로 돌아가라. 특히 **② 예시를 손으로 굴리기** 를 건너뛰고 있다면 그게 원인이다.

## 몸풀기 — easy 세 문제

### 문제 1 — 소포 요금 정산

우체국 소포 요금 규칙은 이렇다.

- 기본 요금: **1kg까지 3,000원.**
- 1kg을 넘긴 무게는 **500g마다 1,000원.** 500g 미만의 나머지도 500g으로 올려 받는다.
- 소포 하나의 상한은 **20,000원.**
- 무게는 `"2kg 300g"` 처럼 kg 칸과 g 칸이 공백을 두고 온다. `"800g"`, `"5kg"` 처럼 한쪽만 올 수도 있다. 무게가 0이면 0원이다.

`fee(무게)` 를 짜라.

```python
fee("800g")       # -> 3000   (1kg 이하 = 기본 요금)
fee("2kg 300g")   # -> 6000   (2,300g = 1,000 + 1,300 -> 500g 블록 3개 -> 3000 + 3*1000)
fee("30kg")       # -> 20000  (초과 29,000g 이지만 상한)
fee("0g")         # -> 0
```

제한 시간 8분. 아래 접근 과정을 보기 전에 반드시 손으로 짜 볼 것.
:::

**어떻게 생각하는가**

- 지문의 단위가 **kg, g, 500g 블록 세 가지**로 섞여 있다. 이걸 그대로 코드에 옮기면 반드시 틀린다. 가장 먼저 할 일은 **가장 작은 단위 하나로 정규화**하는 것이다 — 무게를 전부 **g** 으로 바꾼다. 이 결정 하나로 문제의 절반이 사라진다. [11.1](#/fluency-gap)의 주차 요금에서 `"HH:MM"` 을 분으로 바꾼 것과 정확히 같은 동작이다. **단위가 섞인 지문에서는 언제나 이 한 줄이 먼저 나온다.**
- 무게 문자열은 토큰 두 개까지다. `split()` 으로 쪼개고 토큰마다 접미사를 뗀다. 여기서 판단할 것은 **검사 순서** 하나뿐이다 — `"2kg"` 도 `g` 로 끝나므로 `kg` 를 먼저 물어야 한다([11.3](#/string-toolkit)).
- "500g마다, 나머지도 올려서"는 **올림 나눗셈**이다. `math.ceil(over / 500)` 은 부동소수점을 경유한다. 정수로만 끝내는 관용구가 `-(-over // 500)` 이다. 이 관용구는 격자 문제에서도 계속 나온다.
- 예시 두 번째를 손으로 굴려라. 2,300g → 기본 1,000g을 뺀 1,300g → 500g 블록 3개 → `3000 + 3000 = 6000`. **1,300g에서 블록이 2개가 아니라 3개인 것**이 이 문제에서 가장 많이 틀리는 지점이다.
- 상한은 마지막에 `min` 한 번. 계산 중간에 상한을 걸면 조건문이 늘어나고, 늘어난 조건문에서 틀린다.

**코드**

```python title="parcel.py"
BASE_G, BASE_FEE, UNIT_G, UNIT_FEE, CAP = 1000, 3000, 500, 1000, 20000


def to_gram(text):
    total = 0
    for tok in text.split():                   # "2kg 300g" -> ["2kg", "300g"]
        if tok.endswith("kg"):                 # 긴 접미사를 먼저 본다
            total += int(tok.removesuffix("kg")) * 1000
        else:
            total += int(tok.removesuffix("g"))
    return total


def fee(weight):
    grams = to_gram(weight)
    if grams <= 0:
        return 0
    over = max(0, grams - BASE_G)
    blocks = -(-over // UNIT_G)                # 500g 단위 올림
    return min(BASE_FEE + blocks * UNIT_FEE, CAP)


for w in ["800g", "1kg", "1kg 1g", "2kg", "2kg 300g", "30kg", "0g"]:
    print(f"{w:9} {to_gram(w):6,d}g  {fee(w):7,d}원")
```

**실행 결과**

```text nolines
800g         800g    3,000원
1kg        1,000g    3,000원
1kg 1g     1,001g    4,000원
2kg        2,000g    5,000원
2kg 300g   2,300g    6,000원
30kg      30,000g   20,000원
0g             0g        0원
```

세 번째 줄을 봐라. **1g을 넘긴 순간 1,000원이 붙는다.** 올림 규칙이 있는 요금표는 원래 이렇게 생겼고, 이 줄이 나오는지가 올림을 제대로 짰는지의 신호다.

::: danger 흔한 실수
**하나. 접미사를 글자 수로 자른다.** `"kg"` 는 두 글자, `"g"` 는 한 글자다. 한쪽에 맞춰 잘라 놓으면 다른 쪽이 조용히 망가진다.

```pyrepl
>>> "300g"[:-2]
'30'
>>> "2kg".endswith("g")
True
```

첫 줄은 300g짜리 소포를 **30g으로 접수한다.** 예외도 경고도 없다. 둘째 줄은 순서 함정이다 — `g` 를 먼저 검사하면 `"2kg"` 가 거기서 걸리고, `int("2k")` 가 되어 `ValueError` 로 죽는다. 이쪽은 시끄럽게 죽으니 차라리 운이 좋은 경우다. **긴 접미사부터 검사하고, 뗄 때는 글자 수가 아니라 `removesuffix` 로 무엇을 떼는지 이름을 박아라**([11.3](#/string-toolkit)).

**둘. 올림을 `over // 500 + 1` 이나 `round` 로 처리한다.** 여기서 `over` 는 기본 1,000g을 뺀 **초과 무게**다. `over // 500 + 1` 은 `over` 가 정확히 500의 배수일 때 블록이 하나 더 붙는다 — 초과 1,000g이면 2개인데 3개로 센다. `round` 는 반대로 초과 1,001g에서 2개로 내려 버린다(`round(2.002)` 는 2다). `-(-over // UNIT_G)` 은 두 경우를 모두 맞춘다. 참고로 `(over + UNIT_G - 1) // UNIT_G` 는 같은 값을 주는 다른 표기다([11.1](#/fluency-gap)) — 틀린 것은 "블록을 세고 하나 더한다"는 발상 쪽이다.
:::

::: tip 변형 문제
- **부피 무게가 더 크면 그쪽으로 매긴다면?** 요금 함수는 손대지 않는다. 무게를 정하는 단계가 앞에 붙고 `max` 한 줄이 된다. **요금 규칙과 무게 산정은 다른 책임**이다([12.2](#/requirements-to-model)).
- **요금 구간이 표로 주어지면?** `if/elif` 사다리를 쌓지 말고 `bisect` 로 구간을 찾아라([11.2](#/stdlib-arsenal)의 구간표 조회).
- **고객별 하루 총액에 상한을 걸면?** 상한의 주체가 "소포 하나"에서 "고객"으로 바뀐다. `min` 을 걸 자리가 `fee` 밖으로 나가고, 고객번호를 키로 하는 누적이 필요해진다([11.11](#/drill-hash)).
:::

### 문제 2 — 사물함 비밀번호 검증

사물함 비밀번호가 규칙을 만족하는지 검사한다. **깨진 규칙 코드를 아래 순서대로 전부** 담은 리스트를 반환한다. 다 통과하면 빈 리스트다.

| 코드 | 규칙 |
| --- | --- |
| `LEN` | 길이가 8자 이상 12자 이하 |
| `DIGIT` | `0`~`9` 숫자가 하나 이상 |
| `UPPER` | 영문 대문자가 하나 이상 |
| `SPECIAL` | `!@#$%` 중 하나 이상 |
| `SPACE` | 공백류 문자가 하나도 없다 |
| `LOCKER` | 사물함 번호를 부분 문자열로 포함하지 않는다 |
| `REPEAT` | 같은 문자가 3번 연속되지 않는다 |

```python
broken("Abcd12!x",  "0417")   # -> []
broken("abcd1234",  "0417")   # -> ['UPPER', 'SPECIAL']
broken("Aaaa!0417", "0417")   # -> ['LOCKER', 'REPEAT']
broken("aB!1",      "0417")   # -> ['LEN']
```

::: quiz 먼저 직접 풀어라
제한 시간 10분. 아래 접근 과정을 보기 전에 반드시 손으로 짜 볼 것.
:::

**어떻게 생각하는가**

- "규칙 일곱 개"와 "**전부** 반환"이라는 두 단어가 코드 모양을 정한다. `if not 조건: return [...]` 조기 반환은 못 쓴다 — 첫 위반에서 나가 버린다. **`(이름, 판정)` 표를 만들고 걸러내는 형태**다([11.3](#/string-toolkit)).
- 여기서 표의 값이 **함수가 아니라 불리언**인 것에 주의해라. [11.3](#/string-toolkit)의 재고 코드 검증에서는 앞 규칙이 뒤 규칙의 전제였기 때문에 `lambda` 로 감싸 단락 평가에 태워야 했다. 이 문제의 일곱 규칙은 **서로 독립**이고 어느 하나도 예외를 던지지 않는다. 전제가 없으면 감쌀 이유도 없다. **규칙 사이에 의존이 있는지를 먼저 보고 모양을 고른다.**
- "하나 이상 있다"는 전부 `any(...)`, "하나도 없다"는 `not any(...)` 다. 문장을 그대로 옮기면 된다.
- "같은 문자가 3번 연속"만 관용구를 알아야 한다. 인덱스를 굴리지 말고 **문자열을 한 칸씩 밀어 세 개를 나란히 세워라**. `zip(pw, pw[1:], pw[2:])` 는 짧은 문자열에서 알아서 빈 결과가 되므로 길이 검사가 필요 없다([11.4](#/array-grid)의 `zip(a, a[1:])`, 곧 `pairwise`([11.2](#/stdlib-arsenal))의 발상을 셋으로 늘린 것이다).
- 반환 순서가 지문의 표 순서와 같아야 한다. **리스트로 규칙을 나열하는 것 자체가 순서의 명세**다. `dict` 나 `set` 으로 담으면 그 명세가 사라진다.

**코드**

```python title="locker.py"
SPECIALS = "!@#$%"


def broken(pw, locker):
    rules = [
        ("LEN",     8 <= len(pw) <= 12),
        ("DIGIT",   any(c.isdecimal() for c in pw)),
        ("UPPER",   any("A" <= c <= "Z" for c in pw)),
        ("SPECIAL", any(c in SPECIALS for c in pw)),
        ("SPACE",   not any(c.isspace() for c in pw)),
        ("LOCKER",  locker not in pw),
        ("REPEAT",  not any(a == b == c for a, b, c in zip(pw, pw[1:], pw[2:]))),
    ]
    return [name for name, ok in rules if not ok]


for pw in ["Abcd12!x", "abcd1234", "Aaaa!0417", "aB!1", "Ab 12!xyz", ""]:
    print(f"{pw!r:12} -> {broken(pw, '0417')}")
```

**실행 결과**

```text nolines
'Abcd12!x'   -> []
'abcd1234'   -> ['UPPER', 'SPECIAL']
'Aaaa!0417'  -> ['LOCKER', 'REPEAT']
'aB!1'       -> ['LEN']
'Ab 12!xyz'  -> ['SPACE']
''           -> ['LEN', 'DIGIT', 'UPPER', 'SPECIAL']
```

마지막 줄을 봐라. **빈 비밀번호가 `SPACE`·`LOCKER`·`REPEAT` 를 "통과"한다.** "금지된 것이 없는가"를 묻는 규칙은 빈 입력에서 자동으로 만족된다([11.3](#/string-toolkit)의 `all([]) == True` 와 같은 논리다). 여기서는 `LEN` 이 먼저 막아 주니 무해하지만, 길이 규칙이 없는 문제에서는 그대로 구멍이 된다.

::: danger 흔한 실수
**하나. `isupper()` 와 `isdigit()` 은 유니코드 전체를 통과시킨다.** 지문이 "영문 대문자", "0~9 숫자"라고 말했다면 이 둘은 오답이다.

```pyrepl
>>> "Ω".isupper()
True
>>> "²".isdigit(), "²".isdecimal()
(True, False)
>>> "٣".isdecimal()
True
```

`isdigit()` 은 제곱 기호를 숫자로 세고, `isdecimal()` 도 아라비아-인도 숫자를 통과시킨다. ASCII로 한정하려면 `"A" <= c <= "Z"` 나 `c in string.ascii_uppercase` 처럼 **범위를 직접 못 박아라.** 반대로 "`int()` 가 받는 숫자인가"를 물을 때는 `isdecimal()` 이 맞다. **기준이 무엇인지 정하고 고르는 것**이 요점이다.

**둘. 연속 3회 검사를 인덱스로 짜다가 경계에서 틀린다.** `range(len(pw) - 2)` 는 길이가 1일 때 `range(-1)` 이라 마침 안전하지만, `range(len(pw))` 안에서 `pw[i+2]` 를 읽으면 `IndexError` 다. `zip` 은 가장 짧은 것에서 멈추므로 이 실수 자체가 불가능하다.

```pyrepl
>>> list(zip("ab", "b", ""))
[]
```
:::

::: tip 변형 문제
- **"일곱 규칙 중 다섯 개 이상 만족하면 통과"** 로 바뀌면? `sum(ok for _n, ok in rules) >= 5` 다. 불리언이 정수로 더해지는 성질이 여기서 값을 한다. 표의 값이 함수였다면 이 한 줄이 안 나온다.
- **`LOCKER` 를 대소문자 무시로** 바꾸면 `locker not in pw.lower()` 다. 그런데 사물함 번호가 숫자면 아무 차이가 없다 — **요구사항이 실제로 무엇을 바꾸는지** 확인하고 코드를 늘려라([12.2](#/requirements-to-model)의 YAGNI).
- **깨진 규칙마다 한국어 안내 문구를 함께** 반환해야 하면 표에 칸을 하나 더 붙인다. 함수는 손대지 않는다.
:::

### 문제 3 — 센서 상태 로그 디코딩

센서 상태 로그는 **상태 이름과 반복 횟수가 번갈아 붙은** 한 줄 문자열로 압축돼 온다. 상태 이름은 영문 **대문자**만, 횟수는 **1 이상**의 정수다.

`decode(압축문자열)` 은 상태를 순서대로 펼친 리스트를 반환한다. 형식이 어긋나면 `None` 이다.

```python
decode("ON3OFF2")        # -> ['ON', 'ON', 'ON', 'OFF', 'OFF']
decode("ERR1")           # -> ['ERR']
decode("ON3OFF12ERR2")   # -> ON 3개 + OFF 12개 + ERR 2개 = 원소 17개짜리 리스트
decode("ON")             # -> None   (횟수가 없다)
decode("3ON")            # -> None   (횟수가 먼저 나왔다)
decode("ON0")            # -> None   (횟수는 1 이상)
decode("on3")            # -> None   (소문자)
```

::: quiz 먼저 직접 풀어라
제한 시간 12분. 아래 접근 과정을 보기 전에 반드시 손으로 짜 볼 것.
:::

**어떻게 생각하는가**

- 구분자가 **없다.** `split` 을 쓸 자리가 아니다. 대신 지문에 **"번갈아"** 라는 단어가 있다. 경계는 문자의 **종류가 바뀌는 지점**이다 — 글자에서 숫자로, 숫자에서 글자로.
- "종류가 바뀌는 지점"은 곧 **연속된 같은 종류의 덩어리**다. 연속이 조건이면 `itertools.groupby` 다([11.2](#/stdlib-arsenal)). `groupby("ON3OFF12", key=str.isdecimal)` 이면 `['ON', '3', 'OFF', '12']` 로 정확히 갈라진다 — 두 자리 숫자 `12` 도 한 덩어리로 붙어 나온다. 인덱스를 손으로 미는 `while` 루프를 안 써도 된다.
- 손으로 굴려 보면 검증 조건이 저절로 나온다. 올바른 입력은 **`(글자, 숫자)` 쌍이 반복**되는 모양이다. 그러면 틀린 입력은 셋뿐이다. ① 덩어리 개수가 홀수(짝이 안 맞는다) ② 쌍의 앞이 숫자(순서가 뒤집혔다) ③ 이름이 대문자 영문이 아니다. **`None` 을 반환할 조건을 지문에서 찾지 말고, 올바른 모양을 정의한 뒤 거기서 벗어나는 경우를 세라.**
- 짝을 만드는 법: `tokens[::2]` 와 `tokens[1::2]` 를 `zip` 한다. 앞의 확장 슬라이스가 0·2·4번째(이름)를, 뒤가 1·3·5번째(횟수)를 뽑고 `zip` 이 둘을 나란히 세운다([1.3](#/sequences)의 확장 슬라이스). 단 `zip` 은 남는 하나를 **조용히 버리므로**, 덩어리 개수가 홀수인지 검사하는 줄이 `zip` 보다 앞에 있어야 한다.
- `[name] * n` 으로 펼친다. 리스트 반복은 얕은 복사지만 **원소가 문자열(불변)이라 안전**하다. 여기에 가변 객체가 들어가면 [11.4](#/array-grid)의 2차원 리스트 함정과 같은 사고가 난다.

**코드**

```python title="sensor_decode.py"
from itertools import groupby


def decode(spec):
    tokens = [(is_num, "".join(g)) for is_num, g in groupby(spec, key=str.isdecimal)]
    if not tokens or len(tokens) % 2 == 1:
        return None                                  # 이름과 횟수가 짝을 못 이룬다
    out = []
    for (lhs_num, name), (rhs_num, cnt) in zip(tokens[::2], tokens[1::2]):
        if lhs_num or not rhs_num:                   # 순서가 뒤집혔다
            return None
        if not (name.isalpha() and name.isupper()):
            return None
        n = int(cnt)
        if n == 0:
            return None
        out += [name] * n
    return out


for s in ["ON3OFF2", "ERR1", "ON3OFF12ERR2", "ON", "3ON", "ON0", "on3", "ON-2"]:
    r = decode(s)
    shown = r if r is None or len(r) <= 5 else f"{r[:3]} ... (총 {len(r)}개)"
    print(f"{s!r:14} -> {shown}")
```

**실행 결과**

```text nolines
'ON3OFF2'      -> ['ON', 'ON', 'ON', 'OFF', 'OFF']
'ERR1'         -> ['ERR']
'ON3OFF12ERR2' -> ['ON', 'ON', 'ON'] ... (총 17개)
'ON'           -> None
'3ON'          -> None
'ON0'          -> None
'on3'          -> None
'ON-2'         -> None
```

`"ON-2"` 를 따로 막지 않았는데도 `None` 이 나왔다. `-` 는 숫자가 아니니 `"ON-"` 이 한 덩어리로 묶이고, `isalpha()` 가 그것을 걸러낸다. **올바른 모양을 정의해 두면 예상 못 한 쓰레기 입력이 공짜로 걸러진다.**

::: danger 흔한 실수
`groupby` 의 그룹은 **다음 그룹으로 넘어가는 순간 비워진다.** 나중에 쓰려고 저장해 두면 전부 빈 것이 된다.

```pyrepl
>>> from itertools import groupby
>>> saved = [(k, g) for k, g in groupby("ON3OFF2", key=str.isdecimal)]
>>> [(k, list(g)) for k, g in saved]
[(False, []), (True, []), (False, []), (True, [])]
>>> [(k, "".join(g)) for k, g in groupby("ON3OFF2", key=str.isdecimal)]
[(False, 'ON'), (True, '3'), (False, 'OFF'), (True, '2')]
```

예외도 경고도 없다. **빈 리스트 네 개**가 나오고, 그걸 검증에 태우면 "형식이 틀렸다"는 오답이 조용히 나간다. 위 코드가 컴프리헨션 **안에서 곧바로 `"".join(g)`** 를 하는 이유가 이것이다. `groupby` 결과를 나중에 쓸 거면 그 자리에서 문자열이나 리스트로 **확정해라.**
:::

::: tip 변형 문제
- **횟수를 생략하면 1로 본다**(`"ONOFF3"`)로 바뀌면? 덩어리 개수가 홀수인 것이 더 이상 오류가 아니다. 짝을 `zip` 으로 만드는 전략 자체를 버리고 **덩어리를 순서대로 훑으며 다음 것이 숫자인지 보는** 모양으로 바뀐다. 조건 한 줄이 아니라 골격이 바뀐다.
- **압축하는 방향**은 `groupby` 한 줄이다([11.2](#/stdlib-arsenal)). 압축과 해제를 둘 다 짜서 `decode(encode(xs)) == xs` 를 무작위 입력으로 검사해 보면, 왕복 검증이 단독 테스트보다 버그를 훨씬 잘 잡는다는 것을 알게 된다([11.7](#/blank-page-routine)).
- **총 개수 상한이 걸리면**(예: 10만 개 초과 시 `None`) 펼치기 전에 `n` 을 누적해 검사해라. 다 펼친 뒤에 세면 이미 메모리를 다 쓴 뒤다.
:::

## 본 드릴 — medium 네 문제

### 문제 4 — 대출 회원 정보 마스킹

도서관 대출 기록을 외부에 넘기기 전에 개인정보를 가린다. 한 줄은 `이름,전화,이메일` 이고 필드마다 규칙이 다르다.

- **이름** — 1글자면 그대로. 2글자면 뒤 1글자를 `*`. 3글자 이상이면 **첫 글자와 끝 글자만 남기고** 가운데 전부 `*`.
- **전화** — 형식(하이픈 유무)에 관계없이 **마지막 4글자**를 `*`. 전체가 4글자 이하면 전부 `*`.
- **이메일** — `@` 앞부분이 3글자 이상이면 앞 2글자만 남기고 나머지 `*`. 2글자 이하면 전부 `*`. `@` 뒤는 그대로. `@` 가 없으면 전체를 `*`.

```python
mask("김하늘,010-1234-5678,skyfall@lib.kr")
# -> '김*늘,010-1234-****,sk*****@lib.kr'
mask("이도,02-333-1234,ab@x.com")
# -> '이*,02-333-****,**@x.com'
mask("박,01011112222,q@x.com")
# -> '박,0101111****,*@x.com'
```

::: quiz 먼저 직접 풀어라
제한 시간 12분. 아래 접근 과정을 보기 전에 반드시 손으로 짜 볼 것.
:::

**어떻게 생각하는가**

- 필드가 셋이고 규칙이 셋이다. **함수도 셋**이다. 하나에 몰아넣으면 조건문이 여덟 개가 되고, 여덟 개가 되면 어느 예시가 어느 분기를 타는지 추적이 안 된다. 지문이 항목으로 나뉘어 있으면 **함수 경계를 지문에서 그대로 베껴라**([8.6](#/drill-impl)의 단계별 함수 쪼개기와 같은 발상이다).
- 세 규칙에 공통된 모양이 있다. **"몇 글자를 남기고 나머지를 별표로"** 다. 그러면 필요한 것은 `남길 조각 + "*" * 개수` 뿐이고, 개수는 `len(원본) - 남긴 수` 로 계산된다. **가릴 문자를 하나씩 순회할 이유가 없다.**
- 이메일은 `@` 로 딱 한 번 자른다. `split("@")` 은 결과 길이가 1일 수도 2일 수도 있어 매번 `len` 을 재야 한다. `partition("@")` 은 **항상 3개**를 주고 가운데 칸이 빈 문자열인지만 보면 "구분자가 있었는가"가 끝난다([11.3](#/string-toolkit)).
- 예시 세 번째(`"박"`, `"q"`)를 반드시 손으로 굴려라. **경계는 짧은 입력에 있다.** 이 문제에서 틀리는 사람은 전부 세 글자 이상만 보고 짠다.

**코드**

```python title="mask.py"
def mask_name(name):
    if len(name) <= 1:
        return name                                  # 한 글자는 가릴 자리가 없다
    if len(name) == 2:
        return name[0] + "*"
    return name[0] + "*" * (len(name) - 2) + name[-1]


def mask_phone(phone):
    if len(phone) <= 4:
        return "*" * len(phone)
    return phone[:-4] + "****"


def mask_email(email):
    local, at, domain = email.partition("@")
    if not at:
        return "*" * len(email)                      # @ 가 없으면 통째로 가린다
    keep = 2 if len(local) >= 3 else 0
    return local[:keep] + "*" * (len(local) - keep) + at + domain


def mask(record):
    name, phone, email = record.split(",")
    return ",".join([mask_name(name), mask_phone(phone), mask_email(email)])


for rec in ["김하늘,010-1234-5678,skyfall@lib.kr",
            "이도,02-333-1234,ab@x.com",
            "박,01011112222,q@x.com",
            "남궁도현,010-9999-0001,namgung.dh@city.lib.kr"]:
    print(mask(rec))
```

**실행 결과**

```text nolines
김*늘,010-1234-****,sk*****@lib.kr
이*,02-333-****,**@x.com
박,0101111****,*@x.com
남**현,010-9999-****,na********@city.lib.kr
```

::: danger 흔한 실수
**하나. 짧은 입력에서 별표 개수가 음수가 된다.** 그런데 예외가 안 난다.

```pyrepl
>>> name = "박"
>>> name[0] + "*" * (len(name) - 2) + name[-1]
'박박'
```

`"*" * -1` 은 빈 문자열이다. 그래서 길이 1짜리 이름이 **두 글자로 늘어난 채** 조용히 통과한다. 개인정보를 가리는 코드가 개인정보를 늘려서 내보낸다 — 예외로 죽는 것보다 나쁘다. **`"*" * n` 을 쓸 때는 `n` 이 음수가 될 수 있는지 항상 확인해라.**

**둘. 음수 슬라이스도 같은 방식으로 배신한다.**

```pyrepl
>>> "123"[:-4] + "****"
'****'
```

원본 3글자가 결과 4글자가 됐다. 슬라이스는 범위를 벗어나도 죽지 않기 때문이다([11.3](#/string-toolkit)). **길이가 마스킹 폭보다 짧은 경우를 먼저 막는 `if` 한 줄**이 두 함수 모두에 필요하다.
:::

::: tip 변형 문제
- **전화번호는 하이픈을 무시하고 "끝 숫자 4개"만** 가려야 한다면? `"010-1234-5678"` 의 마지막 4글자는 우연히 숫자였을 뿐이다. `"010-1234-56"` 같은 입력에서는 하이픈을 세게 된다. 숫자 위치를 따로 찾아야 하고, 그 순간 `str.translate` 나 인덱스 목록이 등장한다.
- **표시 폭을 맞춰 표로 출력**해야 하면 한글이 두 칸이라 `ljust` 가 어긋난다([11.3](#/string-toolkit)의 `width`/`pad`).
- **원본으로 되돌릴 수 있어야 한다**면 마스킹이 아니라 **가명 처리**다. 되돌리기가 요구사항에 들어오는 순간 문자열 문제가 아니라 매핑 저장 설계 문제로 바뀐다([12.10](#/case-domain-repo)).
:::

### 문제 5 — 한 글자를 지워 회문 만들기

영소문자로 된 문자열이 있다. **문자를 최대 한 개 지워서** 회문(뒤집어도 같은 문자열)으로 만들 수 있으면 `True`, 아니면 `False` 를 반환하는 `almost_palindrome(s)` 를 짜라. 원래부터 회문이면 하나도 안 지워도 되므로 `True` 다. 문자열 길이는 최대 200,000이다.

```python
almost_palindrome("abca")       # -> True   ('b' 또는 'c' 를 지운다)
almost_palindrome("level")      # -> True   (이미 회문)
almost_palindrome("abcda")      # -> False  (한 글자로는 안 된다)
almost_palindrome("raceacar")   # -> True   ('e' 를 지우면 'racacar')
almost_palindrome("abc")        # -> False
```

::: quiz 먼저 직접 풀어라
제한 시간 15분. 아래 접근 과정을 보기 전에 반드시 손으로 짜 볼 것.
:::

**어떻게 생각하는가**

- 길이 20만이라는 숫자가 먼저 접근을 잘라낸다. "모든 위치를 지워 보고 각각 회문인지 확인"은 $O(n^2)$ 다. 20만이면 400억 — 못 쓴다. **입력 크기를 먼저 읽고 후보를 지우는 것**이 순서다([8.4](#/problem-signals)).
- 회문 판정의 기본형은 **양 끝에서 좁혀 오는 두 인덱스**다([7.3](#/two-pointers)). 여기에 "한 번 봐준다"를 얹으면 된다.
- 핵심 통찰은 손으로 굴려야 나온다. `"raceacar"` 의 양 끝을 좁히면 `r=r`, `a=a`, 그다음 `c` vs `a` 에서 처음 어긋난다. 이 시점에서 **지울 수 있는 후보는 딱 두 개뿐이다** — 왼쪽의 `c` 또는 오른쪽의 `a`. 그 바깥은 이미 짝이 맞았고, 그 안쪽을 지우는 것으로는 지금 어긋난 이 쌍을 해결할 방법이 없다. 후보가 둘이면 **둘 다 확인해 보고 하나라도 되면 참**이다.
- 그래서 필요한 것은 "구간 `[i, j]` 가 회문인가"를 답하는 **작은 함수 하나**다. 이것을 분리하지 않으면 `almost_palindrome` 안에 while 루프 세 개가 겹친다. **한 번 봐주는 로직과 순수 판정 로직을 섞지 마라.**
- 어긋나는 지점은 **한 번만** 나올 수 있다. 그 자리에서 답이 확정되므로 `return` 이다. 어긋난 횟수를 세어 가며 계속 도는 코드는 이 문제를 못 푼다(아래 `흔한 실수`).
- 그리고 이 문제는 **무식한 방법을 짜기 쉽다.** 모든 삭제 후보를 만들어 `t == t[::-1]` 로 검사하면 다섯 줄이다. 짧은 입력에서 둘을 대조하면 확신이 생긴다([11.7](#/blank-page-routine)).

**코드**

```python title="almost_palindrome.py"
def is_pal(s, i, j):
    while i < j:
        if s[i] != s[j]:
            return False
        i, j = i + 1, j - 1
    return True


def almost_palindrome(s):
    i, j = 0, len(s) - 1
    while i < j:
        if s[i] != s[j]:
            # 왼쪽을 지운 경우와 오른쪽을 지운 경우, 둘 중 하나만 되면 된다
            return is_pal(s, i + 1, j) or is_pal(s, i, j - 1)
        i, j = i + 1, j - 1
    return True


def brute(s):                                   # 무식한 방법: 전부 지워 본다
    cands = [s] + [s[:k] + s[k + 1:] for k in range(len(s))]
    return any(t == t[::-1] for t in cands)


for s in ["abca", "level", "abcda", "abc", "raceacar", "ab", ""]:
    print(f"{s!r:10} {almost_palindrome(s)!s:6} (무식한 방법: {brute(s)})")

import random
for _ in range(200000):
    # 'a' 를 두 번 넣어 글자를 편중시킨다 — 회문이 자주 나와야 검증이 된다
    s = "".join(random.choice("aabc") for _ in range(random.randrange(0, 9)))
    assert almost_palindrome(s) == brute(s), s
print("무작위 20만 건 대조 통과")
```

**실행 결과**

```text nolines
'abca'     True   (무식한 방법: True)
'level'    True   (무식한 방법: True)
'abcda'    False  (무식한 방법: False)
'abc'      False  (무식한 방법: False)
'raceacar' True   (무식한 방법: True)
'ab'       True   (무식한 방법: True)
''         True   (무식한 방법: True)
무작위 20만 건 대조 통과
```

::: danger 흔한 실수
**어긋난 개수를 세서 판정한다.** 가장 많이 나오는 오답이고, 예시 몇 개는 통과한다.

```pyrepl
>>> s = "abcda"
>>> sum(1 for a, b in zip(s, s[::-1]) if a != b)
2
>>> t = "abab"
>>> sum(1 for a, b in zip(t, t[::-1]) if a != b)
4
```

"어긋난 자리가 한 쌍(=2개) 이하면 참"이라는 규칙은 **양쪽에서 틀린다.** `"abcda"` 는 2를 주지만 답은 `False` 다. `"abab"` 는 4를 주지만 `'a'` 하나를 지우면 `"bab"` 이라 답은 `True` 다. 이유는 하나다 — **삭제는 길이의 홀짝을 바꾸고, 그러면 남은 문자들의 짝이 통째로 한 칸씩 밀린다.** 개수 세기는 "**교체**로 몇 글자를 고치면 되는가"에 대한 답이지 삭제에 대한 답이 아니다. 두 연산을 구분하지 않으면 이 유형을 계속 틀린다.
:::

::: tip 변형 문제
- **두 개까지 지울 수 있다**면? 이 코드는 못 쓴다. 어긋난 지점에서 후보가 둘로 갈리고 그 각각에서 다시 둘로 갈리므로, "남은 삭제 횟수"를 인자로 받는 재귀가 된다.
- **삭제가 아니라 교체 한 번**이면 오히려 위 `흔한 실수` 의 개수 세기가 정답이 된다. 어긋난 쌍이 정확히 한 쌍 이하면 참이다. **어느 연산인지가 알고리즘을 통째로 바꾼다.**
- **어느 글자를 지웠는지도 반환**해야 하면 `is_pal` 이 참을 준 쪽의 인덱스를 함께 돌려준다. 둘 다 참일 때 무엇을 고를지는 지문에 물어라([11.13](#/live-coding)).
- **공백·구두점을 무시하고 대소문자를 구분하지 않는다**면 정규화를 먼저 한다([11.3](#/string-toolkit)). 단 이때 반환할 인덱스는 **원본 기준인가 정규화 기준인가**가 새 질문이 된다.
:::

### 문제 6 — 물류 포장 명세 전개

포장 명세는 이런 문법이다.

- 영문 **대문자 한 글자**는 품목 하나를 뜻한다.
- `숫자(내용)` 은 괄호 안의 내용을 그 숫자만큼 반복한다. 숫자는 **1 이상**이고 여러 자리일 수 있다.
- 반복은 **중첩**될 수 있다.

`expand(명세)` 는 전개된 품목 문자열을 반환한다. 문법이 어긋나면 `None` 이다.

```python
expand("AB2(C)")      # -> 'ABCC'
expand("2(A3(B))C")   # -> 'ABBBABBBC'
expand("12(A)")       # -> 'AAAAAAAAAAAA'
expand("A(B)")        # -> None   (반복 횟수가 없다)
expand("2(AB")        # -> None   (괄호가 안 닫혔다)
expand("A)B")         # -> None   (열리지 않은 괄호를 닫았다)
```

::: quiz 먼저 직접 풀어라
제한 시간 20분. 아래 접근 과정을 보기 전에 반드시 손으로 짜 볼 것.
:::

**어떻게 생각하는가**

- **"중첩"** 이라는 단어 하나가 자료구조를 정한다. 중첩은 "안쪽이 끝나면 바깥쪽으로 돌아간다"는 뜻이고, 그건 **스택**이다([7.7](#/stack-queue)). `replace` 나 `split` 으로 어떻게든 해 보려는 시도는 두 겹째에서 무너진다.
- 무엇을 쌓는지가 이 문제의 전부다. 괄호를 만나 안쪽으로 들어갈 때 **잃어버리면 안 되는 것**이 둘 있다. ① 지금까지 만든 결과 ② 이 괄호를 몇 번 반복할지. 그래서 스택에 `(지금까지의 결과, 반복 횟수)` 를 맡기고, 손에 든 결과는 **비운 채** 안으로 들어간다. `)` 를 만나면 맡긴 것을 되찾아 `맡긴 결과 + 안에서 만든 것 * 횟수` 로 합친다.
- `"2(A3(B))C"` 를 손으로 굴려라. 이걸 안 하고 코드를 짜면 반드시 틀린다.

```text nolines
  spec        stack                 cur
  2(          [("", 2)]             []
  A           [("", 2)]             ['A']
  3(          [("", 2), ("A", 3)]   []
  B           [("", 2), ("A", 3)]   ['B']
  )           [("", 2)]             ['ABBB']
  )           []                    ['ABBBABBB']
  C           []                    ['ABBBABBB', 'C']
```

- 검증 조건도 이 표에서 그대로 읽힌다. `)` 를 만났는데 스택이 비어 있으면 오류. 다 훑었는데 스택이 남아 있으면 오류. **괄호 짝 검사를 따로 짜지 마라** — 스택의 상태가 이미 답이다.
- 여러 자리 숫자 때문에 `for c in spec` 이 아니라 **인덱스 `i` 를 직접 미는 `while`** 이 된다. 숫자를 만나면 숫자가 끝나는 곳까지 `j` 를 밀어 한꺼번에 `int()` 한다. `for` 로 짜고 싶으면 문제 3처럼 `groupby` 로 먼저 토막 내는 길도 있다.
- 이 문제는 **완전 검증이 가능하다.** `A B 1 2 ( )` 여섯 글자로 만들 수 있는 길이 6 이하의 모든 문자열에 대해, 재귀 하강 파서로 짠 두 번째 구현과 결과를 대조하면 확신이 생긴다.

**코드**

```python title="expand.py"
def expand(spec):
    stack, cur, i, n = [], [], 0, len(spec)
    while i < n:
        c = spec[i]
        if c.isdecimal():
            j = i
            while j < n and spec[j].isdecimal():      # 여러 자리 숫자
                j += 1
            k = int(spec[i:j])
            if k == 0 or j == n or spec[j] != "(":
                return None
            stack.append(("".join(cur), k))           # 지금까지의 결과를 맡겨 둔다
            cur, i = [], j + 1
        elif c == ")":
            if not stack:
                return None
            prefix, k = stack.pop()
            cur, i = [prefix + "".join(cur) * k], i + 1
        elif c.isalpha() and c.isupper():
            cur.append(c)
            i += 1
        else:
            return None
    return None if stack else "".join(cur)


for s in ["AB2(C)", "2(A3(B))C", "12(A)", "A(B)", "2(AB", "A)B", "0(A)", "2(a)"]:
    print(f"{s!r:12} -> {expand(s)!r}")
```

**실행 결과**

```text nolines
'AB2(C)'     -> 'ABCC'
'2(A3(B))C'  -> 'ABBBABBBC'
'12(A)'      -> 'AAAAAAAAAAAA'
'A(B)'       -> None
'2(AB'       -> None
'A)B'        -> None
'0(A)'       -> None
'2(a)'       -> None
```

::: danger 흔한 실수
**하나. 스택에 반복 횟수만 쌓는다.** 가장 흔한 오답이다. `"AB2(C)"` 에서 `)` 를 만났을 때 곱해야 하는 것은 `"ABC"` 가 아니라 **괄호 안의 `"C"` 뿐**이다. 괄호에 들어갈 때 `cur` 을 스택에 맡기고 **비우지** 않으면 바깥에 있던 `"AB"` 까지 함께 반복되어 `"ABCABC"` 가 나온다. 스택에 담는 것이 `(맡긴 결과, 횟수)` 인 이유가 이것이다.

**둘. 여러 자리 숫자를 한 글자로 읽는다.** `for c in spec` 으로 짜면 `"12(A)"` 가 `1` 과 `2` 로 쪼개진다. 예시에 두 자리 숫자가 없으면 통과하고 **채점 데이터에서만 틀린다.** 지문이 "여러 자리일 수 있다"고 말하지 않았어도, 숫자를 읽을 때는 항상 "이 숫자는 몇 자리까지 오는가"를 물어라([11.14](#/exam-debug)).
:::

::: tip 변형 문제
- **결과 길이만 물으면** 전개하지 마라. `cur` 을 문자열이 아니라 **정수 개수**로 바꾸면 스택 골격이 그대로 동작한다. 차이는 극적이다 — `"9("` 를 12겹 중첩한 명세의 결과 길이는 $9^{12} = 282{,}429{,}536{,}481$ 이라 전개하면 메모리가 터지지만, 개수만 곱하면 즉시 끝난다. **"만들라"와 "몇 개인지 말하라"는 다른 문제다.**
- **품목 이름이 여러 글자**(`SKU`)로 늘어나면 문자를 하나씩 읽는 전략이 깨진다. 먼저 토큰으로 쪼개는 단계가 앞에 붙는다.
- **`3A` 처럼 괄호 없는 반복**도 허용하면 "숫자 뒤에는 반드시 `(`" 라는 전제가 사라진다. 검증 한 줄이 아니라 파싱 규칙이 바뀐다.
:::

### 문제 7 — 펌웨어 버전 태그 정렬

센서 펌웨어 버전 태그는 `v메이저.마이너.패치` 형식이고, 뒤에 `-rc숫자` 가 붙으면 **정식 배포 전의 후보판**이다. 후보판은 같은 번호의 정식판보다 **앞선다.**

`sort_versions(태그목록)` 은 `(오름차순 정렬된 올바른 태그, 형식이 틀린 태그)` 를 반환한다. 틀린 태그는 **입력 순서를 유지**한다.

```python
sort_versions(["v1.2.10", "v1.10.0-rc2", "v1.10.0", "v1.2.9"])
# -> (['v1.2.9', 'v1.2.10', 'v1.10.0-rc2', 'v1.10.0'], [])

sort_versions(["v2.0.0", "1.0.0", "v1.0", "v1.0.0-rc10", "v1.0.0-rc2", "v1.0.0-beta"])
# -> (['v1.0.0-rc2', 'v1.0.0-rc10', 'v2.0.0'], ['1.0.0', 'v1.0', 'v1.0.0-beta'])
```

::: quiz 먼저 직접 풀어라
제한 시간 15분. 아래 접근 과정을 보기 전에 반드시 손으로 짜 볼 것.
:::

**어떻게 생각하는가**

- 첫 문장에서 정해지는 것은 **문자열로 비교하면 안 된다**는 것이다. 검증과 정렬을 한꺼번에 하는 방법은 하나뿐이다 — **태그를 튜플로 번역하는 함수 하나.** 번역이 되면 올바른 태그이고, 그 튜플이 곧 정렬 키다. `None` 을 돌려주면 틀린 태그다. **검증과 키 계산을 같은 함수에서 끝내라.** 두 함수로 나누면 파싱 로직이 두 곳에 복제된다.
- 키의 칸 순서는 지문의 우선순위 순서다. `(메이저, 마이너, 패치, 단계, 후보번호)`. **`단계` 칸이 이 문제의 핵심**이다. rc가 정식보다 앞서려면 rc에 `0`, 정식에 `1` 을 준다. 정식판에는 후보번호가 없으니 `0` 을 채운다. 튜플 비교는 앞 칸이 같을 때만 뒤 칸을 보므로, **없는 값에 무엇을 채울지**를 정하는 것이 튜플 키 설계의 절반이다([11.6](#/sorting-as-tool)).
- `-` 로 한 번 자른다. 여기도 `partition` 이다 — 결과가 항상 3개라 `if len(...)` 이 사라진다.
- `"v1.0"` 처럼 칸 수가 모자란 것, `"1.0.0"` 처럼 `v` 가 없는 것, `"v1.0.0-beta"` 처럼 rc가 아닌 꼬리가 붙은 것을 각각 어디서 걸러낼지 정한다. 순서대로 **접두사 → 칸 수 → 숫자 여부 → 꼬리 형식**이다. 앞의 검사가 뒤의 전제다.
- 마지막 함정은 성능이 아니라 습관이다. `sorted(..., key=version_key)` 로 쓰면 **필터링에서 한 번, 정렬에서 또 한 번** 파싱한다. 키를 미리 계산해 `(키, 태그)` 목록을 만들면 태그당 한 번이다([11.6](#/sorting-as-tool)).
- 그 목록을 **튜플째로** `sorted` 에 넣지는 마라. 키가 같을 때 태그 문자열로 2차 정렬이 붙어 입력 순서가 깨진다. `"v1.2.3-rc2"` 와 `"v1.2.3-rc02"` 는 둘 다 키가 `(1, 2, 3, 0, 2)` 라 실제로 이 일이 벌어진다. `key=lambda p: p[0]` 로 **키만 비교**하면 파이썬 정렬의 안정성이 동점 태그의 입력 순서를 지켜 준다([11.6](#/sorting-as-tool)).

**코드**

```python title="versions.py"
def version_key(tag):
    """올바른 형식이면 정렬 키 튜플, 아니면 None."""
    if not tag.startswith("v"):
        return None
    body, dash, rc = tag[1:].partition("-")
    nums = body.split(".")
    if len(nums) != 3 or not all(p.isdecimal() for p in nums):
        return None
    if dash:
        if not rc.startswith("rc") or not rc[2:].isdecimal():
            return None
        stage, order = 0, int(rc[2:])                 # rc 가 정식보다 앞선다
    else:
        stage, order = 1, 0
    return (*map(int, nums), stage, order)


def sort_versions(tags):
    keyed = [(version_key(t), t) for t in tags]       # 키는 태그당 한 번만 계산한다
    ok = [(k, t) for k, t in keyed if k is not None]
    good = [t for _k, t in sorted(ok, key=lambda p: p[0])]   # 키만 비교한다
    bad = [t for k, t in keyed if k is None]
    return good, bad


print(sort_versions(["v1.2.10", "v1.10.0-rc2", "v1.10.0", "v1.2.9"]))
print(sort_versions(["v2.0.0", "1.0.0", "v1.0", "v1.0.0-rc10", "v1.0.0-rc2", "v1.0.0-beta"]))
print(version_key("v1.10.0-rc2"), version_key("v1.10.0"))
```

**실행 결과**

```text nolines
(['v1.2.9', 'v1.2.10', 'v1.10.0-rc2', 'v1.10.0'], [])
(['v1.0.0-rc2', 'v1.0.0-rc10', 'v2.0.0'], ['1.0.0', 'v1.0', 'v1.0.0-beta'])
(1, 10, 0, 0, 2) (1, 10, 0, 1, 0)
```

::: danger 흔한 실수
**버전 태그를 그냥 `sorted` 에 넣는다.** 사전순은 자릿수를 모른다.

```pyrepl
>>> sorted(["v1.2.10", "v1.10.0", "v1.2.9"])
['v1.10.0', 'v1.2.10', 'v1.2.9']
>>> "v1.10.0" < "v1.2.10"
True
```

`"10"` 이 `"2"` 보다 작다고 판정된다 — 첫 글자 `'1'` 이 `'2'` 보다 작으니까. 이 오답이 위험한 이유는 **버전이 한 자리 숫자만 있을 동안은 완벽하게 동작한다**는 것이다. `v1.9.0` 다음에 `v1.10.0` 이 나오는 순간 정렬이 뒤집힌다. 실무에서도 배포 스크립트가 이렇게 조용히 망가진다.

같은 함정이 파일명(`"img2" < "img10"`), 좌석 번호, 층수 문자열에 전부 있다. **"숫자가 들어 있는 문자열을 정렬한다"는 문장을 보면 반드시 숫자를 꺼내 튜플 키로 만들어라.**
:::

::: tip 변형 문제
- **`v01.2.3` 을 거부**해야 하면 규칙이 하나 늘어난다. `isdecimal()` 만으로는 통과하므로 `p == str(int(p))` 같은 검사가 필요하다. 지금 코드는 `(1, 2, 3, 1, 0)` 을 돌려주고 정상으로 취급한다.
- **`-rc2` 외에 `-beta`, `-alpha` 도 허용**하고 `alpha < beta < rc < 정식` 순서라면? `단계` 칸을 사전 하나로 뽑아라. `{"alpha": 0, "beta": 1, "rc": 2}` 를 두고 정식은 `3`. 지금처럼 `0`/`1` 을 코드에 박아 두면 단계가 늘 때마다 숫자를 전부 다시 매겨야 한다.
- **내림차순, 그리고 정식판만** 원하면? 정렬을 뒤집기 전에 필터를 먼저 걸어라. `reverse=True` 와 `sorted(...)[::-1]` 의 차이(동점자 순서가 뒤집힌다)는 [7.4](#/sorting)에, `reverse=True` 가 튜플 키 전체에 걸린다는 것은 [11.6](#/sorting-as-tool)에 있다.
:::

## 요약

- **문제의 어떤 단어가 도구를 부르는가.** "번갈아" → 종류가 바뀌는 경계 → `groupby`. "중첩" → 스택. "숫자가 섞인 문자열을 정렬" → 튜플 키. "규칙 전부 반환" → 규칙 표. 이 회로가 유창함의 실체다.
- **단위를 먼저 하나로 정규화해라.** 무게를 g 하나로 바꾸는 한 줄이 요금 계산의 절반을 지운다. 무게도, 시각도, 버전도, 좌표도 같다.
- **검증 조건은 지문에서 세지 말고 "올바른 모양"을 정의한 뒤 그 여집합으로 잡아라.** 문제 3에서 막지도 않은 `"ON-2"` 가 공짜로 걸러진 것이 그 결과다.
- **조용히 틀리는 세 가지를 외워라.** `"*" * 음수` 는 빈 문자열, 범위를 벗어난 슬라이스는 예외 대신 짧은 결과, `groupby` 의 그룹은 넘어가면 비워진다.
- **경계는 짧은 입력에 있다.** 빈 문자열, 한 글자, 두 글자. 예시를 손으로 굴릴 때 가장 짧은 것부터 넣어라.
- **삭제와 교체는 다른 연산이다.** 어긋난 개수를 세는 판정은 교체의 답이지 삭제의 답이 아니다. 지문의 동사를 정확히 읽어라.
- **무식한 방법을 함께 짜고 무작위 입력으로 대조해라.** 문제 5의 코드가 그 형태이고, 문제 6도 같은 방식으로 완전 검증할 수 있다. 시험장에서 이 습관이 제출 전 마지막 5분을 구한다([11.14](#/exam-debug)).

## 몸풀기 — easy 세 문제

### 문제 1 — 자판기 보충 목록

자판기 슬롯별 재고표(`{슬롯코드: 수량}`)와 판매 로그(팔린 슬롯 코드가 한 건씩 담긴 리스트)가 주어진다.

- 남은 재고가 `threshold` **이하**인 슬롯을 **남은 수량이 적은 순, 같으면 슬롯 코드 사전순**으로 `(슬롯, 남은수량)` 리스트로 반환한다.
- 판매 로그에 재고표에 **없는 슬롯 코드**가 섞여 있으면 무시한다(오작동 기록).
- 판매 수량이 재고를 넘는 일은 없다.

```python
STOCK = {"A1": 5, "A2": 2, "B1": 10, "B2": 0}
LOG = ["A1", "A1", "B1", "A1", "A2", "C9", "B1"]

restock(STOCK, LOG, 0)   # -> [('B2', 0)]
restock(STOCK, LOG, 2)   # -> [('B2', 0), ('A2', 1), ('A1', 2)]
restock(STOCK, LOG, 8)   # -> [('B2', 0), ('A2', 1), ('A1', 2), ('B1', 8)]
```

제한 시간 8분. 아래 접근 과정을 보기 전에 반드시 손으로 짜 볼 것.

**어떻게 생각하는가**

- 컬렉션이 **둘** 있다. 재고표와 판매 로그. 이때 첫 질문은 항상 같다 — **어느 쪽을 순회하는가.** 답은 지문에 있다. "재고표에 없는 슬롯은 무시한다"는 문장이 **재고표를 순회하라**고 말한다. 로그를 순회하면 `C9` 가 결과에 끼어들고, 그걸 막는 `if` 를 따로 붙이게 된다.
- 로그는 세기만 한다. `Counter(log)` 한 줄이고, 조회할 때 **없는 슬롯이 자동으로 0** 이 되므로 "한 번도 안 팔린 슬롯"을 따로 처리할 필요가 없다([11.2](#/stdlib-arsenal)). 도구의 기본값이 요구사항과 일치하는 드문 경우다.
- "적은 순, 같으면 코드순"은 `key=lambda p: (p[1], p[0])` 이다. **문장의 순서가 튜플 칸의 순서**다([11.6](#/sorting-as-tool)).
- 손으로 굴려라. `B2` 는 처음부터 재고 0이고 한 번도 안 팔렸다. **가장 시급한 보충 대상이 로그에 없다.** 이 한 줄을 확인하는 것이 이 문제의 전부다.

**코드**

```python title="vending_restock.py"
from collections import Counter


def restock(stock, log, threshold):
    sold = Counter(log)                                   # 없는 슬롯은 0을 준다
    left = {slot: qty - sold[slot] for slot, qty in stock.items()}
    low = [(slot, n) for slot, n in left.items() if n <= threshold]
    return sorted(low, key=lambda p: (p[1], p[0]))        # 적은 순, 같으면 코드순


STOCK = {"A1": 5, "A2": 2, "B1": 10, "B2": 0}
LOG = ["A1", "A1", "B1", "A1", "A2", "C9", "B1"]

for t in (0, 2, 8):
    print(f"threshold={t} -> {restock(STOCK, LOG, t)}")
```

**실행 결과**

```text nolines
threshold=0 -> [('B2', 0)]
threshold=2 -> [('B2', 0), ('A2', 1), ('A1', 2)]
threshold=8 -> [('B2', 0), ('A2', 1), ('A1', 2), ('B1', 8)]
```

::: danger 흔한 실수
**`Counter` 뺄셈으로 잔량을 구하면 재고 0인 슬롯이 사라진다.**

```pyrepl
>>> from collections import Counter
>>> stock = {"A1": 5, "A2": 2, "B2": 0}
>>> dict(Counter(stock) - Counter(["A1", "A1", "A2"]))
{'A1': 3, 'A2': 1}
```

`B2` 가 통째로 없다. `-` 는 다중집합 뺄셈이라 **0 이하가 된 키를 결과에서 지운다**([11.2](#/stdlib-arsenal)). 이 문제에서 그 키는 정확히 **가장 급하게 보충해야 하는 슬롯**이다. 한 줄이 짧아지는 대가로 요구사항의 핵심이 조용히 날아간다.

여기서 배울 것은 `Counter` 의 동작이 아니라 판단이다. **도구의 기본값이 "0을 버리는 쪽"인지 "0을 남기는 쪽"인지 확인하고 골라라.** 잔량·차이·재고를 다루는 문제에서 0은 버릴 값이 아니라 답이다.
:::

::: tip 변형 문제
- **"품절 슬롯을 맨 앞에, 나머지는 코드순"** 으로 바뀌면 키가 `(n != 0, slot)` 이 된다. 불리언이 정렬 키로 쓰이는 전형적인 자리다.
- **슬롯마다 최대 용량이 다르고 "채울 수 있는 개수"를 반환**해야 하면 컬렉션이 셋이 된다. 그래도 순회 대상은 여전히 하나 — **가장 완전한 목록을 가진 쪽**이다.
- **로그가 `(슬롯, 수량)`** 이면 `Counter(log)` 를 못 쓴다. `Counter()` 를 만들고 `sold[slot] += qty` 로 누적해라. "한 건에 하나"인지 "한 건에 여러 개"인지를 지문에서 먼저 확인하는 습관이 여기서 값을 한다.
:::

### 문제 2 — 좌석 예약 요청 처리

좌석 예약 요청이 `(회원ID, 좌석코드)` 리스트로 **들어온 순서대로** 주어진다. 규칙은 둘이다.

- 이미 다른 요청이 확정한 좌석은 배정하지 않는다.
- **한 회원은 좌석을 하나만** 가진다. 이미 좌석을 받은 회원의 추가 요청은 거절한다.

거절된 요청은 아무것도 바꾸지 않는다. `(승인 목록, 거절된 요청의 인덱스 목록)` 을 반환한다. 승인 목록은 요청 순서를 유지한다.

```python
reserve([("kim", "A1"), ("lee", "A1"), ("kim", "B2"), ("park", "B2"), ("choi", "C3")])
# -> ([('kim', 'A1'), ('park', 'B2'), ('choi', 'C3')], [1, 2])

reserve([("kim", "A1"), ("kim", "A1")])   # -> ([('kim', 'A1')], [1])
reserve([])                               # -> ([], [])
```

::: quiz 먼저 직접 풀어라
제한 시간 8분. 아래 접근 과정을 보기 전에 반드시 손으로 짜 볼 것.
:::

**어떻게 생각하는가**

- "이미 ~인가"를 묻는 문장이 **두 개**다. 좌석에 대해 한 번, 회원에 대해 한 번. 그러면 **인덱스도 두 개** 필요하다. `seat_of[회원]` 하나만 두고 좌석 중복까지 잡으려면 매번 값 전체를 훑어야 하고, 그 순간 $O(n^2)$ 이 된다([11.5](#/dict-set-patterns)).
- 자료구조는 목적에서 나온다. 회원 쪽은 나중에 "누가 어느 좌석"을 물을 수 있으니 `dict`, 좌석 쪽은 **존재 여부만** 물으니 `set` 이다. 둘 다 `set` 으로 둬도 이 문제는 풀린다 — 그래도 `dict` 를 고르는 이유는 확장 요구가 붙을 자리를 미리 열어 두는 것이다([12.2](#/requirements-to-model)).
- 두 검사는 **`or` 로 묶어 한 번에** 한다. 거절 처리가 한 곳뿐이어야 "거절은 상태를 안 바꾼다"는 규칙을 실수로 어길 수 없다.
- 첫 예시를 손으로 굴려라. 인덱스 2의 `("kim", "B2")` 가 거절되므로 **`B2` 는 여전히 비어 있고**, 인덱스 3의 `park` 가 그 좌석을 받는다. 거절이 좌석을 잠그는지 아닌지가 이 문제의 갈림길이고, 답은 "아무것도 바꾸지 않는다"는 한 문장에 있다.

**코드**

```python title="seat_reserve.py"
def reserve(requests):
    seat_of, taken = {}, set()          # 회원 -> 좌석, 그리고 이미 나간 좌석
    ok, rejected = [], []
    for i, (member, seat) in enumerate(requests):
        if member in seat_of or seat in taken:
            rejected.append(i)
            continue                    # 거절은 아무 상태도 바꾸지 않는다
        seat_of[member] = seat
        taken.add(seat)
        ok.append((member, seat))
    return ok, rejected


for reqs in [[("kim", "A1"), ("lee", "A1"), ("kim", "B2"),
              ("park", "B2"), ("choi", "C3")],
             [("kim", "A1"), ("kim", "A1")],
             []]:
    print(reserve(reqs))
```

**실행 결과**

```text nolines
([('kim', 'A1'), ('park', 'B2'), ('choi', 'C3')], [1, 2])
([('kim', 'A1')], [1])
([], [])
```

::: danger 흔한 실수
**하나. 승인 여부와 상관없이 상태를 갱신한다.** 통과 여부를 먼저 판정해 두고 `seat_of[member] = seat` 와 `taken.add(seat)` 를 `if` 밖으로 빼서 매번 실행하면 **거절된 요청이 좌석을 잠근다.** 위 예시에서 인덱스 2의 `("kim", "B2")` 가 거절당하면서도 `B2` 를 물고 가므로 `park` 가 그 좌석을 못 받는다. 결과는 예시와 **딱 한 줄만** 다르다 — 첫 줄이 `([('kim', 'A1'), ('choi', 'C3')], [1, 2, 3])` 이 되고 나머지 두 줄은 그대로다. 이런 오답은 예시를 눈으로 대조해도 잘 안 보인다.

같은 "갱신 시점" 실수라도 **요란하게 터지는 형태**가 따로 있다. `taken.add(seat)` 를 문자 그대로 `if` **위로** 올리면 방금 자기가 넣은 좌석 때문에 `seat in taken` 이 항상 참이 되어 **모든 요청이 거절된다.** 첫 예시가 `([], [0, 1, 2, 3, 4])` 로 나오니 한 번만 돌려도 보인다. 위험한 쪽은 이게 아니라 한 줄만 조용히 틀리는 쪽이다.

반대로 **회원 검사와 좌석 검사 사이에 `seat_of[member] = seat` 를 끼우는 변형은 위 세 예시를 전부 통과한다.** 거절이 잠그는 것이 좌석이 아니라 **회원**이기 때문이다. 드러내려면 같은 회원이 두 번 더 요청하는 입력이 필요하다 — `[("kim", "A1"), ("lee", "A1"), ("lee", "B2")]` 의 정답은 `([('kim', 'A1'), ('lee', 'B2')], [1])` 인데 이 변형은 `([('kim', 'A1')], [1, 2])` 를 준다. **주어진 예시를 다 통과하는 것과 맞는 것은 다르다.**

**둘. 거절 인덱스를 `enumerate` 없이 세려고 한다.** `ok` 의 길이나 별도 카운터로 인덱스를 계산하는 코드는 거절이 섞이는 순간 어긋난다. **"몇 번째 요청인가"가 답에 들어가면 `enumerate` 를 먼저 걸어라**([11.4](#/array-grid)).
:::

::: tip 변형 문제
- **회원이 좌석을 반납한다**는 명령이 섞이면 `taken` 에서 지우고 `seat_of` 에서도 지워야 한다. 인덱스가 둘이면 **삭제도 두 곳**이다 — 한쪽만 지우는 것이 이 유형의 대표적 버그다.
- **좌석에 등급이 있고 "가능한 가장 좋은 좌석을 자동 배정"** 으로 바뀌면 `set` 이 아니라 `heapq` 다. "비어 있는가"에서 "빈 것 중 최선"으로 질문이 바뀌면 자료구조가 바뀐다([11.2](#/stdlib-arsenal)).
- **한 회원이 최대 3석까지** 허용되면 `seat_of` 의 값이 개수 또는 리스트가 되고, 검사가 `len(...) >= 3` 이 된다. 상한이 1에서 K로 바뀌는 것은 **`set` 에서 `Counter` 로 가는 신호**다.
:::

### 문제 3 — 노선 통행량 상위 K

물류 운송 기록이 `(출발지, 도착지)` 리스트로 주어진다. 지점 코드는 **대문자 세 글자**고 출발지와 도착지가 같은 기록은 없다. 노선은 **방향을 구분하지 않는다** — `("SEO", "BSN")` 과 `("BSN", "SEO")` 는 같은 노선이다.

통행량이 많은 상위 `k` 개 노선을 `("코드-코드", 횟수)` 로 반환한다. 노선 표기는 두 코드를 **사전순**으로 붙인다. 통행량이 같으면 **노선 표기 사전순**이다.

```python
T1 = [("SEO", "BSN"), ("BSN", "SEO"), ("SEO", "DJN"),
      ("DJN", "SEO"), ("SEO", "BSN"), ("GWJ", "DJN")]
busiest_routes(T1, 2)   # -> [('BSN-SEO', 3), ('DJN-SEO', 2)]
busiest_routes(T1, 5)   # -> [('BSN-SEO', 3), ('DJN-SEO', 2), ('DJN-GWJ', 1)]

T2 = [("DJN", "GWJ"), ("BSN", "SEO"), ("GWJ", "DJN"), ("SEO", "BSN")]
busiest_routes(T2, 2)   # -> [('BSN-SEO', 2), ('DJN-GWJ', 2)]
```

::: quiz 먼저 직접 풀어라
제한 시간 10분. 아래 접근 과정을 보기 전에 반드시 손으로 짜 볼 것.
:::

**어떻게 생각하는가**

- **"방향을 구분하지 않는다"** 가 이 문제의 유일한 난관이다. 세는 것은 `Counter` 로 끝나므로, 남는 질문은 하나다 — **무엇을 키로 세는가.** 원본 튜플을 그대로 세면 `("SEO","BSN")` 과 `("BSN","SEO")` 가 다른 키가 된다.
- 그러면 "같다"의 정의를 계산식으로 만든다. **순서를 무시한 짝의 표준형은 `tuple(sorted(pair))`** 다([11.5](#/dict-set-patterns)의 정규화 키 표). `frozenset` 도 되지만 두 코드가 같을 때 원소가 하나로 줄고 출력 순서도 보장되지 않으니, **정렬된 튜플을 기본값으로 삼아라.**
- 정규화 키를 정하면 표기 규칙이 공짜로 따라온다. 지문이 "사전순으로 붙인다"고 했으니 키가 이미 그 순서다. **정규화 형태와 출력 형태를 일치시키면 변환 코드가 사라진다.**
- 마지막 문장이 `most_common` 을 배제한다. **동점 규칙이 명시돼 있으면 `most_common` 을 쓰지 마라.** 정렬 기준이 `(-횟수, 노선)` 으로 지문에 그대로 적혀 있다.

**코드**

```python title="routes.py"
from collections import Counter


def busiest_routes(trips, k):
    hits = Counter(tuple(sorted(p)) for p in trips)        # 방향을 지운다
    ranked = sorted(hits.items(), key=lambda kv: (-kv[1], kv[0]))
    return [(f"{a}-{b}", n) for (a, b), n in ranked[:k]]


T1 = [("SEO", "BSN"), ("BSN", "SEO"), ("SEO", "DJN"),
      ("DJN", "SEO"), ("SEO", "BSN"), ("GWJ", "DJN")]
T2 = [("DJN", "GWJ"), ("BSN", "SEO"), ("GWJ", "DJN"), ("SEO", "BSN")]

print(busiest_routes(T1, 2))
print(busiest_routes(T1, 5))
print(busiest_routes(T2, 2))
```

**실행 결과**

```text nolines
[('BSN-SEO', 3), ('DJN-SEO', 2)]
[('BSN-SEO', 3), ('DJN-SEO', 2), ('DJN-GWJ', 1)]
[('BSN-SEO', 2), ('DJN-GWJ', 2)]
```

::: danger 흔한 실수
**`most_common` 의 동점 순서는 정렬이 아니라 삽입 순서다.** 정규화를 제대로 해도 여기서 틀린다.

```pyrepl
>>> from collections import Counter
>>> trips = [("DJN", "GWJ"), ("BSN", "SEO"), ("GWJ", "DJN"), ("SEO", "BSN")]
>>> Counter(trips).most_common()
[(('DJN', 'GWJ'), 1), (('BSN', 'SEO'), 1), (('GWJ', 'DJN'), 1), (('SEO', 'BSN'), 1)]
>>> hits = Counter(tuple(sorted(p)) for p in trips)
>>> hits.most_common(2)
[(('DJN', 'GWJ'), 2), (('BSN', 'SEO'), 2)]
>>> sorted(hits.items(), key=lambda kv: (-kv[1], kv[0]))
[(('BSN', 'SEO'), 2), (('DJN', 'GWJ'), 2)]
```

두 번째 줄이 정규화를 빼먹은 결과다 — 노선 네 개가 각각 1회로 갈렸다. 그리고 정규화한 뒤에도 `most_common(2)` 은 `DJN-GWJ` 를 먼저 준다. 둘 다 2회인데 **먼저 들어온 쪽**이 앞에 오기 때문이다. 정답은 사전순이라 `BSN-SEO` 가 먼저다.

`most_common` 은 내부적으로 `heapq.nlargest`(또는 `sorted`)를 개수만 보고 돌린다. 개수가 같은 원소들의 상대 순서는 **입력 순서에 따라 달라지는 값**이고, 문제의 동점 규칙과는 아무 관계가 없다. **동점 규칙이 지문에 한 줄이라도 있으면 `sorted` 에 키를 직접 써라.**
:::

::: tip 변형 문제
- **방향을 구분한다**로 바뀌면 정규화를 지우기만 하면 된다. 정규화 한 줄이 조건 전체를 담당하고 있다는 뜻이다 — 좋은 설계의 신호다.
- **"통행량이 가장 많은 지점"** 을 물으면 키가 짝이 아니라 **지점 하나**가 된다. 기록 하나가 지점 두 개를 올리므로 `Counter` 에 두 번 더한다. 세는 단위가 바뀌면 키가 바뀐다([11.5](#/dict-set-patterns)).
- **노선이 수십만 개고 상위 10개만** 필요하면 `sorted` 대신 힙이 이긴다. 단 동점 규칙 때문에 `nlargest` 로는 안 된다 — 횟수는 내림차순, 노선은 오름차순이라 방향이 섞였고 **문자열에는 음수 트릭을 못 쓴다**([11.6](#/sorting-as-tool)). 답은 `heapq.nsmallest(k, hits.items(), key=lambda kv: (-kv[1], kv[0]))` 다. 방향이 섞인 키에서는 **작은 쪽을 뽑는 함수로 바꾸는 것**이 정석이다. 상위 K에서 힙과 정렬이 갈리는 기준은 [11.2](#/stdlib-arsenal)에 측정과 함께 있다.
:::

## 본 드릴 — medium 네 문제

### 문제 4 — 합이 정해진 두 박스 짝 짓기

박스 무게가 정수 리스트로 주어진다. **서로 다른 두 박스**를 골라 합이 정확히 `target` 이 되는 **순서 없는 짝의 개수**를 반환하는 `pair_count(weights, target)` 을 짜라. 같은 무게의 박스가 여러 개 있을 수 있고, 그것들은 **서로 다른 박스**로 센다. 박스는 최대 20만 개다.

```python
pair_count([10, 20, 30, 20, 10], 40)   # -> 3   (10+30, 20+20, 30+10)
pair_count([5, 5, 5], 10)              # -> 3   (세 개 중 둘을 고르는 3가지)
pair_count([20, 20, 20, 20], 40)       # -> 6
pair_count([1, 2], 5)                  # -> 0
```

::: quiz 먼저 직접 풀어라
제한 시간 15분. 아래 접근 과정을 보기 전에 반드시 손으로 짜 볼 것.
:::

**어떻게 생각하는가**

- 20만이라는 숫자가 모든 쌍을 보는 풀이를 지운다. 200억 번이다([8.4](#/problem-signals)). 그러면 남는 길은 하나 — **"짝을 찾는다"를 "짝이 이미 있었는지 조회한다"로 바꾼다.** 합이 정해져 있으니 `w` 의 짝은 `target - w` 로 **계산된다.** 계산되는 것을 찾아다니지 마라.
- 여기서 대부분이 함정에 빠진다. 전체를 먼저 세고 `Counter` 를 순회하면 **각 짝을 두 번 세는 문제**와 **`w` 와 `target - w` 가 같은 경우**를 둘 다 손으로 처리해야 한다. 후자는 $n(n-1)/2$ 이고, 앞의 예시 `[5, 5, 5]` 와 `[20, 20, 20, 20]` 이 정확히 그 경우다. 조건문 두 개가 붙는다.
- **갱신 시점을 옮기면 두 함정이 동시에 사라진다.** 한 번 훑으면서 "지금까지 본 것 중 내 짝의 개수"를 더하고, **그 다음에** 자신을 넣는다. 각 짝은 **뒤쪽 원소가 처리될 때 딱 한 번** 세어지고, 자기 자신은 아직 표에 없으니 `w == target - w` 도 저절로 맞는다. 자료구조를 언제 갱신하는가가 조건문 두 개를 지운다.
- 손으로 굴려라. `[5, 5, 5]`, target 10 → 첫 5는 0(표가 비었다), 둘째 5는 1, 셋째 5는 2. 합 3. 예시와 맞는다.
- 그리고 이 문제는 **무식한 방법이 한 줄**이다. `combinations` 로 모든 쌍을 세면 된다. 작은 무작위 입력으로 대조해라([11.7](#/blank-page-routine)).

**코드**

```python title="pair_boxes.py"
import random
from collections import Counter
from itertools import combinations


def pair_count(weights, target):
    seen, total = Counter(), 0
    for w in weights:
        total += seen[target - w]       # 지금까지 본 것 중 짝이 되는 개수
        seen[w] += 1                    # 자기 자신은 센 다음에 넣는다
    return total


def brute(weights, target):            # 무식한 방법: 모든 쌍
    return sum(1 for a, b in combinations(weights, 2) if a + b == target)


for ws, t in [([10, 20, 30, 20, 10], 40), ([5, 5, 5], 10),
              ([1, 2], 5), ([20, 20, 20, 20], 40), ([], 10)]:
    print(f"{str(ws):22} target={t:2d} -> {pair_count(ws, t)} (무식한 방법: {brute(ws, t)})")

random.seed(3)
for _ in range(20000):
    ws = [random.randrange(1, 8) for _ in range(random.randrange(0, 9))]
    t = random.randrange(2, 15)
    assert pair_count(ws, t) == brute(ws, t), (ws, t)
print("무작위 2만 건 대조 통과")
```

**실행 결과**

```text nolines
[10, 20, 30, 20, 10]   target=40 -> 3 (무식한 방법: 3)
[5, 5, 5]              target=10 -> 3 (무식한 방법: 3)
[1, 2]                 target= 5 -> 0 (무식한 방법: 0)
[20, 20, 20, 20]       target=40 -> 6 (무식한 방법: 6)
[]                     target=10 -> 0 (무식한 방법: 0)
무작위 2만 건 대조 통과
```

::: perf 조회로 바꾸면 두 자릿수 이상 벌어진다
무게 4,000개(값은 1~1,000 범위의 난수라 중복이 많다), `target = 1001` 로 재면 이렇게 나온다.

| 방법 | 1회 |
| --- | --- |
| `Counter` 한 번 훑기 | 0.99 ~ 1.3 ms |
| `combinations` 이중 루프 | 367 ~ 419 ms |

(Python 3.14.0rc2 / Linux 기준 실측. 절대값은 기기마다 다르지만 자릿수 차이는 어디서나 같다.)

$O(n^2)$ 가 $O(n)$ 이 됐으니 **입력이 커질수록 격차도 커진다.** 4,000개에서 이미 300~400배인 이 차이는 20만 개에서는 시간 초과와 통과의 차이가 된다([8.3](#/tle)). 무식한 방법은 **버릴 코드가 아니라 대조용 코드**다 — 작은 입력에서 정답을 확인하는 데 쓰고 제출하지는 마라.
:::

::: danger 흔한 실수
**`Counter` 를 `defaultdict(int)` 로 바꿔도 답은 같지만, 조회만으로 키가 생긴다.**

```pyrepl
>>> from collections import Counter, defaultdict
>>> c = Counter()
>>> c[7]
0
>>> len(c)
0
>>> d = defaultdict(int)
>>> d[7]
0
>>> len(d)
1
```

`seen[target - w]` 는 **없는 짝을 조회하는 일이 대부분**이다. `defaultdict` 로 짜면 그 조회마다 키가 하나씩 생겨 표가 최대 두 배로 부풀고, 순회 중에 조회하면 `RuntimeError` 까지 난다([11.2](#/stdlib-arsenal)). **"읽기만 하는 조회"가 상태를 바꾸는지 알고 골라라.**

**두 번째 실수는 요구사항 오독이다.** "짝의 개수"가 아니라 "**서로 다른 무게 쌍의 종류**"를 묻는 문제도 흔하다. `[20, 20, 20, 20]` 의 답이 6이 아니라 1이 된다. 같은 지문 같은 도구인데 답이 완전히 다르다 — **"몇 쌍"과 "몇 종류"를 지문에서 구분해 읽어라**([11.8](#/function-completion)).
:::

::: tip 변형 문제
- **합이 `target` 이하인 짝의 개수**로 바뀌면 해시가 무용지물이다. `target - w` 가 값 하나가 아니라 범위가 되므로 **정렬 + 투 포인터**로 간다([7.3](#/two-pointers)). 등호가 부등호로 바뀌면 도구가 바뀐다.
- **세 박스의 합**이면 한 개를 고정하고 나머지 둘에 이 기법을 쓴다. $O(n^2)$ 이고, 그게 이 유형의 한계다.
- **짝의 인덱스를 반환**해야 하면 `Counter` 가 아니라 `defaultdict(list)` 에 인덱스를 모은다. 답이 개수가 아니라 위치일 때 자료구조가 바뀌는 것은 [11.6](#/sorting-as-tool)에서 본 것과 같은 패턴이다.
:::

### 문제 5 — 물류 도크 동시 점유

트럭의 도크 사용 기록이 `(도착, 출발)` 분 단위 정수 쌍으로 주어진다. 도크 청소 시간 때문에 **한 트럭의 출발 시각과 다른 트럭의 도착 시각이 같으면 두 트럭이 겹친 것으로 본다.**

동시에 점유된 도크의 **최대 대수**와 그 상태가 **처음 만들어진 시각**을 `(대수, 시각)` 으로 반환해라. 기록이 없으면 `(0, -1)` 이다.

```python
peak_docks([(0, 30), (30, 60), (15, 45)])   # -> (3, 30)
peak_docks([(0, 10), (20, 30)])             # -> (1, 0)
peak_docks([(0, 30), (30, 60)])             # -> (2, 30)
peak_docks([])                              # -> (0, -1)
```

::: quiz 먼저 직접 풀어라
제한 시간 15분. 아래 접근 과정을 보기 전에 반드시 손으로 짜 볼 것.
:::

**어떻게 생각하는가**

- "동시에 최대 몇 개"는 구간을 통째로 다루는 문제가 아니다. **도착을 `+1`, 출발을 `-1` 로 쪼개서 시각 순으로 정렬**하면 2차원 구간 문제가 1차원 스캔으로 납작해진다([11.6](#/sorting-as-tool)의 세 번째 형태).
- 첫 예시를 그림으로 굴려라. 세 트럭이 `t=30` 에서 만난다.

```text nolines
  t         0    15   30   45   60
  truck A   |=========|              0 도착, 30 출발
  truck B             |=========|   30 도착, 60 출발
  truck C        |=========|        15 도착, 45 출발
                      ^ t=30 에 세 대가 동시에 도크를 물고 있다
```

- **이 문제의 전부는 같은 시각의 처리 순서다.** 지문이 "출발과 도착이 같으면 겹친 것으로 본다"고 했으니 **도착을 먼저** 처리해야 한다. 그래서 이벤트를 `(시각, 0=도착)` / `(시각, 1=출발)` 로 만든다. 튜플 정렬이 같은 시각에서 `0` 을 앞에 세운다. 경계 정책을 **정렬 키의 두 번째 칸에 못 박는** 것이 요점이다.
- 반환할 것이 대수만이 아니라 **시각**이라는 데 주의해라. 최댓값이 갱신되는 순간은 항상 도착 이벤트다. `if cur > best` 를 도착 처리 안에 두면 "처음 만들어진 시각"이 저절로 잡힌다. `>=` 로 쓰면 **마지막 시각**이 남아 오답이 된다.
- 무식한 방법도 짜기 쉽다. 0부터 최대 시각까지 모든 정수 시점에서 `a <= t <= b` 를 세면 된다. 작은 무작위 입력으로 대조해라.

**코드**

```python title="dock_peak.py"
def peak_docks(trucks):
    events = []
    for arrive, depart in trucks:
        events.append((arrive, 0))      # 0 이 먼저다 -- 같은 시각은 겹친 것으로 본다
        events.append((depart, 1))
    events.sort()
    cur, best, at = 0, 0, -1
    for t, kind in events:
        if kind == 0:
            cur += 1
            if cur > best:              # 최댓값이 갱신되는 순간의 시각만 남긴다
                best, at = cur, t
        else:
            cur -= 1
    return best, at


for ts in [[(0, 30), (30, 60), (15, 45)], [(0, 10), (20, 30)],
           [(0, 30), (30, 60)], [(5, 5)], []]:
    print(f"{str(ts):34} -> {peak_docks(ts)}")
```

**실행 결과**

```text nolines
[(0, 30), (30, 60), (15, 45)]      -> (3, 30)
[(0, 10), (20, 30)]                -> (1, 0)
[(0, 30), (30, 60)]                -> (2, 30)
[(5, 5)]                           -> (1, 5)
[]                                 -> (0, -1)
```

::: danger 흔한 실수
**`(시각, +1)` / `(시각, -1)` 로 만들어 그냥 정렬한다.** 가장 흔한 오답이고, 겹침 정책이 정반대로 뒤집힌다.

```pyrepl
>>> ev = [(0, 1), (30, -1), (30, 1), (60, -1), (15, 1), (45, -1)]
>>> sorted(ev)
[(0, 1), (15, 1), (30, -1), (30, 1), (45, -1), (60, -1)]
```

`-1 < 1` 이라 **같은 시각에서 출발이 도착보다 먼저** 처리된다. 즉 "30분에 출발하고 30분에 도착하는 것은 겹치지 않는다"는 정책이 된다. 첫 예시의 답이 3이 아니라 **2**가 나오고, 예외도 경고도 없다.

델타 값을 그대로 정렬 키로 쓰는 습관이 문제다. **델타와 정렬 순서는 다른 관심사다.** 순서 필드를 따로 두고(`0`/`1`), 델타는 `kind` 를 보고 결정해라. 이 문제에서 정렬 키의 두 번째 칸은 최적화가 아니라 **요구사항 그 자체**다. 그리고 경계 정책은 지문에 반드시 적혀 있다 — 안 적혀 있으면 그건 되물어야 하는 질문이다([11.13](#/live-coding)).
:::

::: tip 변형 문제
- **"필요한 최소 도크 수"** 는 같은 답이다. 문장이 달라도 계산이 같은 대표적인 짝이다. 반면 **"한 도크로 최대 몇 대를 처리하는가"** 는 완전히 다른 문제로, 출발 시각 기준 그리디가 된다([7.19](#/greedy)).
- **시각이 `"HH:MM"` 문자열**로 오면 분으로 정규화하는 한 줄이 앞에 붙는다([11.9](#/drill-string)의 문제 1).
- **최대 상태가 유지된 구간의 길이**를 물으면 이벤트 스캔만으로는 부족하다. 갱신 시점만이 아니라 **다음 이벤트까지의 간격**을 봐야 하고, 그러면 이벤트를 시각별로 묶어 처리하는 모양으로 바뀐다.
:::

### 문제 6 — 센서 로그 슬라이딩 윈도우

센서 상태 로그가 문자열 리스트로 주어진다. **연속한 `k`개** 구간 중 **서로 다른 상태의 종류 수**가 가장 많은 구간을 찾아 `(시작 인덱스, 종류 수)` 를 반환해라. 종류 수가 같으면 **가장 이른 시작 인덱스**다. 로그 길이가 `k` 보다 짧으면 `(-1, 0)` 이다. 로그는 최대 20만 개다.

```python
widest_window(["ON", "ON", "OFF", "ERR", "ON", "OFF"], 3)   # -> (1, 3)
widest_window(["ON", "ON", "OFF", "ERR"], 2)                # -> (1, 2)
widest_window(["ON", "ON", "ON"], 2)                        # -> (0, 1)
widest_window(["ON"], 2)                                    # -> (-1, 0)
```

::: quiz 먼저 직접 풀어라
제한 시간 15분. 아래 접근 과정을 보기 전에 반드시 손으로 짜 볼 것.
:::

**어떻게 생각하는가**

- 첫 예시를 손으로 굴려라. 창이 한 칸씩 밀린다.

```text nolines
  log       ON  ON  OFF ERR ON  OFF
  i=0      [ON  ON  OFF]                2 종류
  i=1          [ON  OFF ERR]            3 종류  <- 최대, 가장 이른 시작
  i=2              [OFF ERR ON ]        3 종류
  i=3                  [ERR ON  OFF]    3 종류
```

- 굴려 보면 보인다. 창이 한 칸 이동할 때 **바뀌는 것은 양 끝 두 개뿐**이다. 창마다 `set` 을 새로 만들면 같은 값을 $k$ 번씩 다시 읽는다 — $O(nk)$ 다. 20만 × 1,000이면 2억이다.
- 그래서 **창 안의 빈도표를 들고 다니며 갱신**한다. 들어오는 것은 `+1`, 나가는 것은 `-1`. `Counter` 다.
- **핵심은 여기다.** 종류 수는 `len(win)` 인데, `-1` 을 해서 0이 된 키는 `Counter` 에 **그대로 남는다.** 지우지 않으면 `len` 이 "창 안의 종류 수"가 아니라 "지금까지 등장한 종류 수"가 된다. **`del` 한 줄이 이 문제의 정답과 오답을 가른다.**
- 첫 창을 `Counter(log[:k])` 로 만들고 나머지를 루프로 미는 모양이 가장 짧다. 루프 안에서 `i - k` 가 나가는 원소의 인덱스다. **경계 인덱스는 손으로 한 번 확인해라** — `i = k` 일 때 나가는 것이 `log[0]` 이면 맞다.

**코드**

```python title="sensor_window.py"
import random
from collections import Counter


def widest_window(log, k):
    if k <= 0 or len(log) < k:
        return -1, 0
    win = Counter(log[:k])
    best, at = len(win), 0
    for i in range(k, len(log)):
        win[log[i]] += 1
        old = log[i - k]
        win[old] -= 1
        if win[old] == 0:
            del win[old]                # 0 인 키를 지워야 len() 이 종류 수가 된다
        if len(win) > best:
            best, at = len(win), i - k + 1
    return at, best


def brute(log, k):                      # 무식한 방법: 창마다 set 을 새로 만든다
    if k <= 0 or len(log) < k:
        return -1, 0
    best, at = -1, -1
    for i in range(len(log) - k + 1):
        n = len(set(log[i:i + k]))
        if n > best:
            best, at = n, i
    return at, best


for lg, k in [(["ON", "ON", "OFF", "ERR", "ON", "OFF"], 3),
              (["ON", "ON", "OFF", "ERR"], 2),
              (["ON", "ON", "ON"], 2), (["ON"], 2)]:
    print(f"{str(lg):42} k={k} -> {widest_window(lg, k)} (무식한 방법: {brute(lg, k)})")

random.seed(11)
for _ in range(20000):
    lg = [random.choice("abc") for _ in range(random.randrange(0, 10))]
    k = random.randrange(1, 5)
    assert widest_window(lg, k) == brute(lg, k), (lg, k)
print("무작위 2만 건 대조 통과")
```

**실행 결과**

```text nolines
['ON', 'ON', 'OFF', 'ERR', 'ON', 'OFF']    k=3 -> (1, 3) (무식한 방법: (1, 3))
['ON', 'ON', 'OFF', 'ERR']                 k=2 -> (1, 2) (무식한 방법: (1, 2))
['ON', 'ON', 'ON']                         k=2 -> (0, 1) (무식한 방법: (0, 1))
['ON']                                     k=2 -> (-1, 0) (무식한 방법: (-1, 0))
무작위 2만 건 대조 통과
```

::: danger 흔한 실수
**0이 된 키를 지우지 않는다.** 위 예시 넷 중 셋은 그래도 통과한다.

```pyrepl
>>> from collections import Counter
>>> win = Counter(["ON", "OFF"])
>>> win["ERR"] += 1
>>> win["ON"] -= 1
>>> win
Counter({'OFF': 1, 'ERR': 1, 'ON': 0})
>>> len(win)
3
>>> len(+win)
2
```

창 안에는 두 종류만 있는데 `len` 이 3이다. 두 번째 예시 `["ON", "ON", "OFF", "ERR"]`, `k=2` 에서 `del` 을 빼면 답이 `(1, 2)` 가 아니라 **`(2, 3)`** 이 된다 — 존재하지 않는 세 종류짜리 창을 보고한다. 첫 예시는 우연히 같은 답이 나오므로 **예시 하나만 맞춰 보고 넘어가면 그대로 오답을 제출한다.**

`+win`(단항 플러스)이 0 이하를 걸러 주긴 한다. 하지만 이건 매번 **새 `Counter` 를 만드는** 연산이라, 창을 밀 때마다 부르면 이동 한 번에 종류 수만큼의 비용이 붙는다. 창을 미는 코드에서는 `del` 한 줄이 맞다.

같은 실수가 "창 안에 특정 값이 있는가", "창 안의 최댓값" 류 문제 전부에 있다. **슬라이딩 윈도우에서 빈도표를 들고 다니면, 나가는 원소를 지우는 코드가 반드시 필요하다.**
:::

::: perf 창마다 다시 세는 것과 밀고 가는 것
상태 8종의 로그 20만 개, `k = 1000` 으로 재면 이렇다.

| 방법 | 1회 |
| --- | --- |
| `Counter` 를 밀고 간다 | 61 ~ 73 ms |
| 창마다 `len(set(...))` | 2.0 ~ 2.9 s |

(Python 3.14.0rc2 / Linux 기준 실측. 절대값은 기기마다 다르지만 자릿수 차이는 어디서나 같다.) 표의 범위는 4라운드에 걸쳐 다시 잰 폭이다. 두 방법 모두 재실행 간 30% 안쪽으로 흔들렸고, **어느 쪽이 빠른지는 한 번도 뒤집히지 않았다.**

$O(nk)$ 와 $O(n)$ 의 차이이므로 **`k` 가 커질수록 격차가 커진다.** `k` 가 10 정도로 작으면 두 방법의 차이는 사라지고, 그때는 짧은 코드를 골라라. 무엇을 고를지는 `k` 가 상수인지 입력에 비례하는지에 달려 있다([7.1](#/complexity)).
:::

::: tip 변형 문제
- **"모든 상태가 다 나오는 가장 짧은 구간"** 이면 창 길이가 고정이 아니다. 양쪽 포인터를 각각 움직이는 가변 창이 되고, 종료 조건이 `len(win) == 전체 종류 수` 로 바뀐다([7.3](#/two-pointers)).
- **"가장 많이 나온 상태"** 를 함께 반환해야 하면 `Counter` 만으로는 창을 밀 때마다 `most_common(1)` 을 불러야 하고, 그 한 번이 종류 수만큼의 비용이다. 종류가 적으면 무해하지만, 종류가 많으면 최댓값을 따로 관리해야 한다.
- **종류 수가 정확히 `m` 인 구간의 개수**를 물으면 정답 판정만 바뀌고 골격은 그대로다. 창을 미는 뼈대가 이 유형 전체에 공통이라는 것을 확인해 봐라.
:::

### 문제 7 — 창고 재고 목록 교차 비교

창고 여러 곳의 SKU 목록이 리스트의 리스트로 주어진다. **한 창고 목록 안에 같은 SKU가 여러 번 나올 수 있다**(입고 건별 기록). `(모든 창고에 다 있는 SKU, 정확히 한 창고에만 있는 SKU와 그 창고 번호)` 를 반환해라. 둘 다 SKU 사전순이고, 창고 번호는 0부터 시작한다. 창고가 없으면 `([], [])` 다.

```python
compare_warehouses([["A", "B", "B", "C"], ["B", "C", "D"], ["C", "B"]])
# -> (['B', 'C'], [('A', 0), ('D', 1)])

compare_warehouses([["A"]])              # -> (['A'], [('A', 0)])
compare_warehouses([["A", "A"], ["B"]])  # -> ([], [('A', 0), ('B', 1)])
compare_warehouses([])                   # -> ([], [])
```

::: quiz 먼저 직접 풀어라
제한 시간 15분. 아래 접근 과정을 보기 전에 반드시 손으로 짜 볼 것.
:::

**어떻게 생각하는가**

- 질문이 둘이고 도구도 둘이다. "모든 창고에 다 있는"은 **교집합**, "정확히 한 창고에만"은 **몇 개의 창고에 등장했는지 세기**다. 전자는 `set` 연산, 후자는 `Counter` 다([11.5](#/dict-set-patterns)).
- 그런데 두 질문에 공통 전제가 있다. **둘 다 "창고 안에서 몇 번"이 아니라 "몇 개의 창고에서"를 묻는다.** 그래서 첫 줄은 정해져 있다 — 목록마다 `set()` 으로 감싸 **창고 안의 중복을 먼저 죽인다.** 이 한 줄을 빼면 `Counter` 가 창고 수가 아니라 입고 건수를 세게 되고, 두 번째 답이 조용히 틀린다.
- 세 번째 예시가 그 함정을 잡는 테스트다. `["A", "A"]` 의 `A` 는 **한 창고에만** 있으므로 답에 들어가야 한다. 정규화를 빼먹으면 `A` 의 개수가 2가 되어 "정확히 하나"에서 탈락한다. **예시에 중복이 일부러 심겨 있으면 그건 함정 신호다.**
- 창고 번호도 필요하다. 세면서 `setdefault` 로 **처음 나온 창고**를 함께 기록해 두면 나중에 다시 찾을 필요가 없다. 개수가 1인 SKU에게는 처음 나온 창고가 곧 유일한 창고다.
- 마지막으로 **퇴화 입력**이다. 창고가 없을 때 `set.intersection(*sets)` 는 예외를 던진다. 빈 입력에서 무엇이 정답인지 지문에 있으니 그것을 먼저 막아라.

**코드**

```python title="warehouse_diff.py"
from collections import Counter


def compare_warehouses(warehouses):
    sets = [set(w) for w in warehouses]      # 창고 안의 중복을 먼저 죽인다
    if not sets:
        return [], []
    common = sorted(set.intersection(*sets))
    hits, first = Counter(), {}
    for i, s in enumerate(sets):
        for sku in s:
            hits[sku] += 1
            first.setdefault(sku, i)         # 처음 나온 창고를 기억한다
    only = sorted((sku, first[sku]) for sku, n in hits.items() if n == 1)
    return common, only


for wh in [[["A", "B", "B", "C"], ["B", "C", "D"], ["C", "B"]],
           [["A"]], [["A", "A"], ["B"]], [[], ["A"]], []]:
    print(f"{str(wh):44} -> {compare_warehouses(wh)}")
```

**실행 결과**

```text nolines
[['A', 'B', 'B', 'C'], ['B', 'C', 'D'], ['C', 'B']] -> (['B', 'C'], [('A', 0), ('D', 1)])
[['A']]                                      -> (['A'], [('A', 0)])
[['A', 'A'], ['B']]                          -> ([], [('A', 0), ('B', 1)])
[[], ['A']]                                  -> ([], [('A', 1)])
[]                                           -> ([], [])
```

네 번째 줄은 지문에 없는 입력이다. 창고 하나가 **비어 있으면 교집합은 무조건 빈 집합**이 되고, `A` 는 실제로 한 창고에만 있으니 `[('A', 1)]` 이 나온다. 우연히 합리적인 답이지만 **그건 확인해 봐야 아는 것**이다. 예시에 없는 퇴화 입력을 직접 넣어 보는 것이 제출 전 마지막 절차다([11.14](#/exam-debug)).

::: danger 흔한 실수
**하나. 중복을 죽이지 않고 원본을 통째로 센다.**

```pyrepl
>>> from collections import Counter
>>> Counter(sku for w in [["A", "A"], ["B"]] for sku in w)
Counter({'A': 2, 'B': 1})
```

`A` 는 창고 하나에만 있는데 2가 나왔다. "정확히 한 창고"를 `n == 1` 로 판정하는 코드가 `A` 를 놓친다. **`Counter` 가 무엇을 세고 있는지 항상 한 문장으로 말해 봐라** — 여기서 세야 하는 것은 "SKU가 등장한 **창고**의 수"다([11.5](#/dict-set-patterns)).

**둘. 빈 입력에서 교집합이 터진다.**

```pyrepl
>>> set.intersection(*[])
Traceback (most recent call last):
  File "<stdin>", line 1, in <module>
    set.intersection(*[])
TypeError: unbound method set.intersection() needs an argument
```

`*` 로 펼치는 코드는 **리스트가 비면 인자가 하나도 없는 호출**이 된다. `sets[0].intersection(*sets[1:])` 로 써도 `sets[0]` 에서 `IndexError` 다. 빈 컬렉션은 "전부 교집합"의 정의가 애매한 자리이므로 **문제가 무엇을 원하는지 확인하고 명시적으로 처리해라.**
:::

::: tip 변형 문제
- **"두 곳 이상에 있는"** 으로 바뀌면 `n == 1` 이 `n >= 2` 다. 세는 것을 제대로 정했으면 조건 한 글자만 바뀐다 — 그게 키를 잘 골랐다는 증거다.
- **어느 창고에 없는지도** 알려면 `first` 하나로는 부족하다. SKU마다 창고 번호 집합을 들고 가는 `defaultdict(set)` 이 되고, 답은 `전체 창고 집합 - 가진 창고 집합` 이다.
- **창고 안 수량까지 비교**하면 `set` 이 아니라 창고별 `Counter` 가 되고, 교집합은 `&` 연산으로 바뀐다. `Counter` 의 `&` 는 각 키의 **최솟값**을 준다 — 그게 "모든 창고가 공통으로 보유한 수량"이다.
:::

## 요약

- **세기 문제에서 시간을 잡아먹는 것은 도구가 아니라 키 결정이다.** `Counter` 를 쓰기 전에 "무엇을 세는가"를 한 문장으로 말해라. 문제 3은 "노선", 문제 7은 "SKU를 가진 창고의 수"다. 이 문장을 못 만들면 코드를 쓰지 마라.
- **컬렉션이 둘 있으면 어느 쪽을 순회할지 지문이 정해 준다.** "없는 것은 무시한다"는 문장이 순회 대상을 지목한다(문제 1).
- **"이미 ~인가"를 묻는 문장이 두 개면 인덱스도 두 개다.** 하나로 버티려 하면 $O(n^2)$ 이 된다(문제 2).
- **정렬 키의 뒤쪽 칸은 최적화가 아니라 요구사항이다.** 동점 규칙이 있으면 `most_common` 을 버리고 `key=(-횟수, 이름)` 을 써라. 경계에서 도착과 출발 중 어느 쪽이 먼저인지도 정렬 키의 두 번째 칸에 못 박는다(문제 3, 5).
- **찾아다니지 말고 계산해라. 그리고 언제 갱신할지를 정해라.** 합이 정해져 있으면 짝은 `target - w` 로 계산되고, 계산되는 것은 해시 조회로 끝난다. 여기에 "세고 나서 넣기"로 갱신 순서까지 바꾸면 중복 계산과 자기 자신 짝 문제가 동시에 사라진다. $O(n^2)$ 이 $O(n)$ 이 되는 순간은 대개 이 두 문장에서 온다(문제 4).
- **조용히 틀리는 셋을 외워라.** `Counter` 뺄셈은 0을 버린다, `-1` 해서 0이 된 키는 남는다, `Counter` 조회는 키를 안 만들지만 `defaultdict` 조회는 만든다.
- **무식한 방법을 함께 짜고 작은 무작위 입력으로 대조해라.** 문제 4와 6의 코드가 그 형태다. 무식한 방법은 버릴 코드가 아니라 정답의 기준이다.

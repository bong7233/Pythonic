# 11.5 딕셔너리와 집합으로 푸는 문제

::: lead
해시 테이블이 어떻게 동작하는지는 [1.6 dict](#/dict)와 [7.6 해시](#/hashing)에서 이미 다뤘다. 그런데 그걸 다 읽고도 빈 화면 앞에서는 여전히 이중 루프를 친다. 이 절이 채우는 것은 지식이 아니라 **문제 문장에서 키를 뽑아내는 회로**다. 다루는 질문은 하나뿐이다 — **"무엇이 같으면 같은 것으로 볼 것인가?"** 그 답이 정해지면 자료구조도, 루프의 모양도, 코드의 길이도 따라서 정해진다.
:::

## 이중 루프가 보이면 키를 못 찾은 것이다

문제. **사원 대여 신청 목록에서 두 번 이상 신청한 사번을 모두 찾아라.**

손이 먼저 움직이는 대로 쓰면 이렇게 된다.

```python title="처음 떠오르는 코드"
def dups_slow(ids):
    out = set()
    for i in range(len(ids)):
        for j in range(i + 1, len(ids)):
            if ids[i] == ids[j]:
                out.add(ids[i])
    return out
```

돌아간다. 그리고 입력이 커지는 순간 죽는다. 같은 답을 내는 코드가 이것이다.

```python title="키를 찾은 코드"
def dups_fast(ids):
    seen, out = set(), set()
    for x in ids:
        if x in seen:
            out.add(x)
        seen.add(x)
    return out
```

두 코드의 차이는 알고리즘 지식이 아니다. **"이미 본 적 있는가"라는 질문을 매번 다시 훑어서 답할 것인가, 기록해 두고 물어볼 것인가**의 차이다. 앞의 코드에는 기억이 없어서 매번 처음부터 다시 센다.

::: perf 기억을 만드는 비용은 공짜에 가깝다
사번 문자열 2만 개(중복 포함)로 위 두 함수를 돌린 결과다.

| 구현 | 2만 개 |
| --- | --- |
| 이중 루프 | 5,700 ~ 7,700 ms |
| `set` 으로 기억 | 2.1 ~ 3.4 ms |

(Python 3.14.0rc2 / Linux 기준 실측. 절대값은 기기마다 다르지만 자릿수 차이는 어디서나 같다.)

**천 배가 넘는다.** 더 중요한 것은 입력이 커질 때 늘어나는 방향이 다르다는 것이다. 같은 입력을 2,000개 → 20,000개로 열 배 늘리면 이중 루프는 72 ms → 7,400 ms 로 **약 100배** 느려지고, `set` 판은 0.20 ms → 2.8 ms 로 **약 14배** 느려진다. 위는 제곱으로, 아래는 선형에 가깝게 늘어난다 — 20만 개까지 키워도 `set` 판은 50 ~ 70 ms다. `set` 판이 정확히 10배가 아닌 것은 집합이 커지면서 캐시 미스와 리해싱이 늘기 때문이고, 그 초과분은 입력이 100배가 되어도 여전히 상수 배에 머문다.
:::

## 던져야 할 질문은 하나다

도구를 고르기 전에 문장을 바꿔야 한다. "무슨 자료구조를 쓰지?"는 답이 안 나오는 질문이다. 대신 이것을 물어라.

```text nolines
      "무엇이 같으면 같은 것으로 볼 것인가?"   -> 그 답이 key 다
      "같은 것끼리 무엇을 모을 것인가?"        -> 그 답이 value 다
```

키가 정해지면 dict 를 쓸지 set 을 쓸지가 저절로 갈린다. **값이 필요하면 dict, 있는지만 알면 set 이다.** 그리고 값의 모양이 자료구조를 확정한다.

```text nolines
  value 가 "몇 개"인가        ->  Counter             개수 자체가 답이다
  value 가 "목록"인가         ->  defaultdict(list)   순서와 중복을 살린다
  value 가 "집합"인가         ->  defaultdict(set)    중복이 저절로 접힌다
  value 가 "첫 등장 하나"인가 ->  dict + setdefault   나중 것은 버린다
  value 가 필요 없다          ->  set                 존재 여부가 답이다
```

::: tip 없는 키를 만났을 때 무엇을 쓰는가
매번 헷갈리는 자리다. 기준은 **"없으면 어떻게 되기를 바라는가"** 하나다.

| 없을 때 원하는 것 | 쓸 것 |
| --- | --- |
| 예외로 알고 싶다 (버그를 숨기지 않겠다) | `d[k]` |
| 기본값을 읽고 끝 | `d.get(k, 0)` |
| 기본값을 **넣고** 이어서 쓴다 | `d.setdefault(k, [])` |
| 모든 키가 항상 기본값을 갖는다 | `defaultdict(...)` |

`get` 과 `setdefault` 의 차이는 **딕셔너리에 흔적을 남기는가**다. `get` 은 읽기만 하고, `setdefault` 는 없으면 만들어 넣은 뒤 그것을 돌려준다. 그래서 `first.setdefault(k, i)` 한 줄이 "첫 등장 위치만 기록하라"를 그대로 표현한다.
:::

## 세기 — 무엇을 세는지가 곧 키다

빈도 세기에서 실수는 `Counter` 를 몰라서 나지 않는다. **무엇을 세야 하는지 문장을 잘못 읽어서** 난다. 같은 로그를 두고도 질문이 바뀌면 키가 바뀐다.

```pyrepl
>>> from collections import Counter
>>> rows = [("kim", "2026-03"), ("kim", "2026-03"), ("lee", "2026-03"), ("kim", "2026-04")]
>>> Counter(m for m, _ in rows)
Counter({'kim': 3, 'lee': 1})
>>> Counter(rows)
Counter({('kim', '2026-03'): 2, ('lee', '2026-03'): 1, ('kim', '2026-04'): 1})
>>> Counter(rows)[("kim", "2026-03")]
2
```

두 번째 줄이 **복합 키**다. "회원별"이 아니라 "회원이 어느 달에"를 물으면 키가 튜플이 된다. 이걸 못 보면 딕셔너리를 두 겹으로 중첩하는 코드로 흘러가고, 그때부터 코드가 길어진다.

두 겹이 실제로 필요한 경우도 있다. **중간 단계에서 그룹 전체를 꺼내 써야 할 때**다.

```pyrepl
>>> from collections import defaultdict
>>> d = defaultdict(lambda: defaultdict(int))
>>> d["2026-03"]["kim"] += 1
>>> d["2026-03"]["lee"] += 2
>>> d["2026-04"]["kim"] += 1
>>> {k: dict(v) for k, v in d.items()}
{'2026-03': {'kim': 1, 'lee': 2}, '2026-04': {'kim': 1}}
```

::: danger 중첩 defaultdict 는 `lambda` 없이 못 만든다
```python
from collections import defaultdict

d = defaultdict(defaultdict(int))           # ❌ TypeError: first argument must be callable or None
d = defaultdict(lambda: defaultdict(int))   # ✅
```

`defaultdict` 의 첫 인자는 **호출 가능한 것**(팩토리)이다. `defaultdict(int)` 는 이미 만들어진 딕셔너리 객체라 팩토리가 아니다. `list` 나 `int` 를 넘길 때 괄호를 안 붙이는 이유도 같다 — 넘기는 것은 **만드는 방법**이지 결과물이 아니다.

`Counter` 도 팩토리로 쓸 수 있다. `defaultdict(Counter)` 는 괄호가 없으니 그대로 동작한다.
:::

`Counter` 자체의 함정(뺄셈이 0 이하를 지우는 것, 없는 키가 조용히 0을 반환하는 것)은 [11.2](#/stdlib-arsenal)에서 다뤘다. 여기서 붙일 것은 하나뿐이다. **세기 문제에서 시간을 잡아먹는 건 도구가 아니라 키 결정이다.** 5초 안에 "무엇을 세는가"를 한 문장으로 못 말하면 코드를 쓰지 마라. 아직 문제를 안 읽은 것이다.

## 묶기 — 그룹핑은 세 개의 결정이다

`defaultdict(list)` 를 쓰는 법은 [11.2](#/stdlib-arsenal)에 있다. 실전에서 막히는 건 문법이 아니라 **세 가지를 각각 정해야 한다는 것을 모를 때**다.

1. **키** — 무엇이 같으면 한 그룹인가
2. **값의 그릇** — `list`(순서·중복 유지) / `set`(중복 제거) / `int`(합계) / `Counter`(그룹 안에서 또 세기)
3. **넣을 것** — 원본 전체인가, 그중 한 필드인가

셋 중 하나만 바꿔도 완전히 다른 코드가 된다. 그리고 실전 문제의 요구사항은 대개 이 셋 중 하나를 건드리는 방식으로 변형된다.

```python title="같은 로그, 세 가지 그룹핑"
from collections import defaultdict, Counter

logs = [("kim", "PY-101"), ("kim", "ML-204"), ("kim", "PY-101"), ("lee", "PY-101")]

borrowed = defaultdict(list)     # "빌린 순서대로 전부"
for m, b in logs:
    borrowed[m].append(b)

distinct = defaultdict(set)      # "몇 종류를 빌렸나"
for m, b in logs:
    distinct[m].add(b)

per_book = defaultdict(Counter)  # "어떤 책을 몇 번씩"
for m, b in logs:
    per_book[m][b] += 1

print(dict(borrowed))                                  # {'kim': ['PY-101', 'ML-204', 'PY-101'], 'lee': ['PY-101']}
print({m: len(s) for m, s in distinct.items()})        # {'kim': 2, 'lee': 1}
print(dict(per_book["kim"]))                           # {'PY-101': 2, 'ML-204': 1}
```

## 정규화 키 — 이 절에서 가장 값어치 있는 도구

여기서부터가 진짜다. **키는 데이터에 이미 있는 필드일 필요가 없다.** 계산해서 만들어도 된다. 그리고 실전 문제의 절반은 그 계산식을 찾아내는 문제다.

가장 유명한 형태가 애너그램이다. **"글자 구성이 같은 단어끼리 묶어라."** 여기서 "같다"의 정의는 문자열 그 자체가 아니라 *정렬된 글자열*이다. 그러면 키도 그것이다. 이 관용구 자체와 "왜 정렬한 값이 키가 되는가"는 [7.6 해시](#/hashing)에서 이미 다뤘다. 여기서 익힐 것은 그 관용구가 아니라 **키 식을 찾아내는 절차와 그 식이 실제로 얼마를 버는지**다.

```pyrepl
>>> from collections import defaultdict
>>> words = ["listen", "silent", "enlist", "google", "elgoog", "banana"]
>>> groups = defaultdict(list)
>>> for w in words:
...     groups["".join(sorted(w))].append(w)
...
>>> dict(groups)
{'eilnst': ['listen', 'silent', 'enlist'], 'eggloo': ['google', 'elgoog'], 'aaabnn': ['banana']}
>>> [g for g in groups.values() if len(g) > 1]
[['listen', 'silent', 'enlist'], ['google', 'elgoog']]
```

이중 루프로 모든 쌍을 비교하는 $O(n^2)$ 풀이가 **한 줄짜리 키 계산**으로 사라졌다. 여기서 배울 것은 애너그램이 아니라 절차다.

> **"같다"의 정의를 문장에서 뽑아 내고, 그 정의를 그대로 계산하는 식을 만든다. 그 식의 결과가 키다.**

정규화 키는 온갖 문제에서 같은 모양으로 나온다.

| 문제가 말하는 "같다" | 키 식 |
| --- | --- |
| 글자 구성만 같으면 | `"".join(sorted(w))` |
| 대소문자·공백 무시 | `s.casefold().replace(" ", "")` |
| 숫자만 같으면 (전화번호, 코드) | `"".join(c for c in s if c.isdigit())` |
| 순서 없는 짝 (A-B 와 B-A 는 같다) | `frozenset({a, b})` 또는 `tuple(sorted((a, b)))` |
| 같은 달이면 | `date[:7]` |
| 기울기가 같으면 | gcd 로 약분한 `(dx, dy)` |

::: danger 정규화가 한 군데라도 빠지면 조용히 틀린다
정규화 키의 유일한 실패 방식은 **같아야 할 두 값이 다른 키가 되는 것**이다. 예외가 안 나므로 눈에 안 띈다.

```pyrepl
>>> from math import gcd
>>> def slope(p, q):
...     dx, dy = q[0] - p[0], q[1] - p[1]
...     g = gcd(dx, dy)
...     return (dx // g, dy // g)
...
>>> slope((0, 0), (2, 4))
(1, 2)
>>> slope((0, 0), (-1, -2))
(-1, -2)
```

같은 방향인데 키가 갈렸다. 약분은 했지만 **부호를 정규화하지 않았다.** 고치면 이렇게 된다.

```pyrepl
>>> from math import gcd
>>> def direction(p, q):
...     dx, dy = q[0] - p[0], q[1] - p[1]
...     g = gcd(dx, dy)
...     dx, dy = dx // g, dy // g
...     if dx < 0 or (dx == 0 and dy < 0):
...         dx, dy = -dx, -dy
...     return (dx, dy)
...
>>> direction((0, 0), (2, 4))
(1, 2)
>>> direction((0, 0), (-1, -2))
(1, 2)
>>> direction((0, 0), (0, -3))
(0, 1)
```

그리고 `p == q` 면 `gcd(0, 0)` 이 0이라 `ZeroDivisionError` 가 난다. **키 함수를 만들면 반드시 "같아야 하는 두 입력"과 "퇴화 입력"을 손으로 한 번씩 넣어 봐라.** 이건 [11.7](#/blank-page-routine)의 검증 단계에서 매번 하는 일이다.
:::

::: danger 키는 해시 가능해야 한다 — `Counter` 와 `list` 는 아니다
글자 구성을 세었으니 `Counter` 를 키로 쓰면 되겠다고 생각하는 순간 막힌다.

```pyrepl
>>> from collections import Counter
>>> {Counter("aab"): 1}
Traceback (most recent call last):
  File "<stdin>", line 1, in <module>
TypeError: cannot use 'collections.Counter' as a dict key (unhashable type: 'Counter')
```

`Counter` 는 `dict` 의 하위 클래스이고 dict 는 가변이라 해시가 없다. **가변 객체에 `__hash__` 가 없는 이유**는 [7.6 해시](#/hashing)에 있다 — 키를 넣은 뒤에 값이 바뀌면 슬롯을 다시 계산할 방법이 없기 때문이다. 여기서 필요한 것은 그 이유가 아니라 **불변 형태로 굳히는 방법**이다.

```pyrepl
>>> from collections import Counter
>>> tuple(sorted(Counter("aab").items()))
(('a', 2), ('b', 1))
>>> {tuple(sorted(Counter("aab").items())): 1}
{(('a', 2), ('b', 1)): 1}
```

`sorted` 를 빼면 안 된다. 딕셔너리의 순회 순서는 **삽입 순서**라 `tuple(Counter("aab").items())` 는 `(('a', 2), ('b', 1))`, `tuple(Counter("baa").items())` 는 `(('b', 1), ('a', 2))` 가 된다. 같아야 할 둘이 다른 키가 되는 것이다. `frozenset(...items())` 로 감싸면 순서가 사라져 이 문제는 없지만, 출력 순서를 보장하지 않아 디버깅할 때 읽기 나쁘다. **정렬한 튜플을 기본값으로 삼아라.** 좌표를 담을 때 리스트 대신 튜플을 쓰는 이유도 같다([11.4](#/array-grid)).
:::

::: perf 애너그램 키 — `sorted` 가 이론상 더 느린데 실제로는 더 빠르다
`"".join(sorted(w))` 는 단어 길이 $k$ 에 대해 $O(k \log k)$ 이고, 알파벳 26칸 카운트 배열은 $O(k)$ 다. 복잡도만 보면 후자가 이긴다. 비교한 카운트 구현은 이것이다.

```python title="26칸 카운트 키 — 측정에 쓴 구현"
def count_key(w):
    c = [0] * 26
    for b in w.encode():        # 문자열이 아니라 바이트를 순회한다 (ord() 호출이 사라진다)
        c[b - 97] += 1
    return bytes(c)             # 리스트는 해시 불가능하므로 굳힌다
```

**총 글자 수를 80만으로 고정하고 단어 길이만 바꿔 재면 이렇게 나온다.**

| 단어 길이 × 개수 | `"".join(sorted(w))` | `count_key(w)` |
| --- | --- | --- |
| 8 × 100,000 | 61 ~ 70 ms | 82 ~ 94 ms |
| 50 × 16,000 | 67 ~ 69 ms | 34 ~ 39 ms |
| 200 × 4,000 | 84 ~ 96 ms | 28 ~ 36 ms |
| 1000 × 800 | 98 ~ 105 ms | 27 ~ 32 ms |

(Python 3.14.0rc2 / Linux 기준 실측, 각 칸은 5회 중 최소~최대. 카운트 열은 위의 `w.encode()` 구현이다 — 구현을 바꾸면 이 열의 값이 바뀐다. 절대값은 기기마다 다르지만 자릿수 차이는 어디서나 같다.)

**짧은 단어에서는 `sorted` 가 이긴다.** 정렬은 C에서 끝나지만 카운트 루프는 글자마다 파이썬 바이트코드를 밟기 때문이다. 단어가 길어질수록 그 루프 비용이 분산되고, 이 구현·이 환경에서는 **길이 12~16 부근에서 순서가 뒤집혔다.**

역전 지점을 정하는 것은 단어 길이만이 아니라 **카운트 루프를 어떻게 짰는가**다. 위 구현에서 `w.encode()` 를 `w` 로, `bytes(c)` 를 `tuple(c)` 로 바꾸면(교과서에 흔한 `for ch in w: c[ord(ch) - 97] += 1` 형태) 글자마다 `ord()` 호출이 하나 더 붙어 8글자에서 89 ~ 95 ms 로 느려지고, **역전 지점이 20~24로 밀린다.** 복잡도는 그대로인데 상수가 달라져서 결론이 뒤집히는 것이다 — 그래서 이런 판단은 추론이 아니라 측정으로 해야 한다.

실전 판단은 간단하다. **단어가 짧으면(수십 글자 이하) 고민하지 말고 `sorted`.** 코드가 한 줄이고 더 빠르기까지 하다. 유전체 서열처럼 긴 문자열을 다룰 때만 카운트 배열을 꺼내라. 이런 종류의 "복잡도와 실측이 어긋나는" 지점은 [7.2](#/py-ds-cost)에서 더 다룬다.
:::

## 중복 제거 — 순서를 지켜야 하는가

"중복을 없애라"는 문장을 보면 손이 `set()` 으로 간다. 그 전에 **출력 순서에 조건이 붙어 있는지** 반드시 확인해라.

```pyrepl
>>> seats = ["A3", "B1", "A3", "C7", "B1", "A3"]
>>> list(dict.fromkeys(seats))
['A3', 'B1', 'C7']
>>> sorted(set(seats))
['A3', 'B1', 'C7']
```

`dict.fromkeys` 는 **첫 등장 순서를 유지**한다. 파이썬 3.7부터 dict 가 삽입 순서를 보장하기 때문에 성립하는 관용구다. `set` 은 순서를 잃는다.

::: warn `set` 을 그대로 출력하면 채점에서 떨어진다
`print(set(seats))` 의 출력 순서는 **실행할 때마다 달라진다.** 3.3부터 `str` 과 `bytes` 의 해시는 프로세스마다 다른 무작위 시드로 계산되기 때문이다([1.7](#/sets)에 측정과 함께 있다. 그 시드가 왜 도입됐는지는 [1.6](#/dict)의 PEP 456 이야기다). 로컬에서 우연히 맞아 보이고 채점 서버에서 틀리는 전형적인 원인이다 — 정수 집합만 보고 "정렬돼 나온다"고 믿는 것도 같은 함정이다.

**집합을 출력할 일이 있으면 반드시 `sorted()` 를 거쳐라.** 순서가 요구사항에 있으면 애초에 `set` 이 아니라 `dict.fromkeys` 를 쓴다.
:::

원소가 해시 불가능하면 그대로는 못 넣는다. 그리고 **일부 필드만 같으면 중복**인 경우가 실전에서는 더 흔하다. 이때는 키만 집합에 넣고 원본은 따로 모은다.

```python title="부분 키 중복 제거 — 첫 기록을 남긴다"
def dedup_first(rows, keyfn):
    seen, out = set(), []
    for r in rows:
        k = keyfn(r)
        if k not in seen:
            seen.add(k)
            out.append(r)
    return out


rows = [("kim", "A3", "09:00"), ("kim", "A3", "09:01"), ("lee", "B1", "09:02")]
print(dedup_first(rows, lambda r: (r[0], r[1])))
# [('kim', 'A3', '09:00'), ('lee', 'B1', '09:02')]
```

**마지막 기록을 남겨야 한다면** 코드가 더 짧아진다. `{keyfn(r): r for r in rows}` 로 덮어쓰고 `.values()` 를 꺼내면 끝이다. 요구사항의 "첫"과 "마지막" 한 글자가 코드 모양을 바꾼다.

## 두 컬렉션 비교 — 기호 하나가 이중 루프 하나다

`&` `-` `^` `<=` 자체는 [11.2](#/stdlib-arsenal)와 [1.7](#/sets)에 있다. 여기서 훈련할 것은 **지문의 표현을 기호로 옮기는 것**이다.

| 문제가 말하는 것 | 연산 |
| --- | --- |
| "양쪽에 다 있는", "공통으로" | `a & b` |
| "A에는 있고 B에는 없는", "누락된" | `a - b` |
| "한쪽에만 있는", "달라진 것" | `a ^ b` |
| "필요한 것을 전부 갖췄는가" | `need <= have` |
| "겹치는 게 하나도 없는가" | `a.isdisjoint(b)` |

::: danger 개수를 묻는 문제에 `set` 을 쓰면 조용히 틀린다
```python
from collections import Counter

need = ["볼트", "볼트", "너트", "와셔"]
have = ["볼트", "너트", "너트"]

print(set(need) - set(have))          # {'와셔'}  ← 볼트가 하나 부족한 사실이 사라졌다
print(Counter(need) - Counter(have))  # Counter({'볼트': 1, '와셔': 1})
```

**지문에 "몇 개"가 들어 있으면 `set` 이 아니다.** `set` 은 원소의 존재만 기억하고 개수는 버린다. 재고 대조, 부품 수량, 티켓 매수처럼 수량이 있는 문제는 전부 다중집합(`Counter`) 문제다. 판단 기준은 하나다 — **답이 "어느 것"이면 `set`, "몇 개"면 `Counter`.**
:::

::: perf "겹치는가"만 물을 때는 교집합을 만들지 마라
`bool(a & b)` 는 **교집합 전체를 새로 만든 뒤** 비었는지 본다. `isdisjoint` 는 하나라도 겹치는 순간 멈춘다. 겹치는 원소가 순회 앞쪽에 있으면 **수천 배 이상** 벌어지고, 하나도 겹치지 않으면 둘 다 전부 훑어야 하므로 격차가 사라진다. 조기 종료의 내부 동작과 측정은 [1.7 set과 frozenset](#/sets)에 있다.

여기서 남길 것은 하나다. **`isdisjoint` 가 손해 보는 경우는 없으므로, 지문이 "겹치는가"만 물으면 위 표의 마지막 줄을 쓴다.** 개수도 목록도 필요 없는데 교집합을 만들어 놓는 코드는 요구사항을 잘못 읽은 흔적이다.
:::

## `in` 이 $O(1)$ 이라는 사실이 알고리즘을 바꾼다

이게 이 절에서 가장 중요한 이야기다. 앞의 패턴들은 코드를 짧게 만들었지만, 이건 **접근 자체를 바꾼다.**

::: perf 컨테이너 한 글자 바꾸는 것으로 수천에서 수만 배
사번 문자열 10만 개에서 1,000번 조회했을 때다.

| 컨테이너 | 1,000회 조회 |
| --- | --- |
| `list` | 740 ~ 910 ms |
| `set` | 0.04 ~ 0.30 ms |

(Python 3.14.0rc2 / Linux 기준 실측. 절대값은 기기마다 다르지만 자릿수 차이는 어디서나 같다.)

`in` 이라는 **똑같은 글자**가 한쪽에서는 전체 훑기, 다른 쪽에서는 해시 한 번이다. 코드 겉모습이 같아서 리뷰에서도 잘 안 잡힌다. 자료구조별 실제 비용은 [7.2](#/py-ds-cost)에 정리돼 있다.
:::

두 수의 합 문제가 대표적이다. **"합이 정확히 예산과 같은 두 좌석이 있는가."** 모든 쌍을 보면 $O(n^2)$ 이지만, "내가 찾는 짝이 이미 지나갔는가"를 $O(1)$ 로 물을 수 있으면 한 번 훑고 끝난다.

```python title="한 번 훑기로 끝난다"
def has_pair(prices, budget):
    seen = set()
    for p in prices:
        if budget - p in seen:      # 짝이 이미 지나갔는가
            return True
        seen.add(p)
    return False


print(has_pair([12000, 9000, 15000, 7000], 21000))   # True
print(has_pair([12000, 9000, 15000, 7000], 30000))   # False
print(has_pair([15000, 15000], 30000))               # True  (같은 값 두 개도 짝이 된다)
print(has_pair([15000], 30000))                      # False (자기 자신과는 짝이 안 된다)
```

`seen.add(p)` 가 **검사 뒤에** 오는 순서가 마지막 두 줄의 결과를 만든다. 순서를 바꾸면 `budget - p == p` 인 원소 하나만으로 짝이 성립해 버린다. 깨지는 범위는 "원소가 하나일 때"가 아니다 — **예산의 절반이 목록에 한 번이라도 들어 있으면 전부 틀린다.** 위 네 줄 중 네 번째뿐 아니라 **두 번째 줄(`[12000, 9000, 15000, 7000], 30000`)까지 `False` 대신 `True` 로 뒤집힌다.** 15000 하나가 자기 자신과 짝을 지어서다. 한 줄을 위로 옮긴 것치고는 파괴 범위가 넓고, 예시를 두 개만 돌려 보면 놓친다.

더 극적인 예가 연속 구간이다. **"대출된 도서 번호 중 연속으로 이어지는 가장 긴 구간의 길이."** 정렬하면 $O(n \log n)$ 이지만, 집합이 있으면 정렬 없이 끝난다.

```python title="시작점만 세면 전체가 O(n) 이다"
def longest_run(book_ids):
    s = set(book_ids)
    best = 0
    for x in s:
        if x - 1 in s:              # 구간의 시작점이 아니면 건너뛴다
            continue
        length = 1
        while x + length in s:
            length += 1
        best = max(best, length)
    return best


print(longest_run([104, 101, 102, 300, 103, 301]))   # 4
print(longest_run([7]))                              # 1
print(longest_run([]))                               # 0
```

`while` 이 안에 있어서 $O(n^2)$ 처럼 보이지만 아니다. **`if x - 1 in s` 를 통과하는 원소는 각 구간의 시작점 하나뿐이고**, 각 원소는 정확히 한 번만 `while` 에 방문된다. 전체가 $O(n)$ 이다. 이 "시작점만 세는" 발상은 집합 조회가 공짜일 때만 가능하다.

::: danger 루프 안에서 `set()` 을 다시 만들면 전부 없던 일이 된다
```python
for q in queries:
    if q in set(pool):      # ❌ 매 반복마다 집합을 통째로 새로 만든다
        ...
```

사번 문자열 5만 개를 담은 `pool` 에 조회 100회를 돌리면 **240 ~ 300 ms 대 2.8 ~ 3.4 ms** 였다(집합을 루프 앞에서 한 번만 만든 쪽이 뒤 숫자다. Python 3.14.0rc2 / Linux 기준 실측. 절대값은 기기마다 다르지만 자릿수 차이는 어디서나 같다). 원소가 정수면 문자열 해시가 사라져 절대값이 3분의 1로 떨어지지만 — 84 ms 대 0.73 ms — **비율은 양쪽 다 100배 안팎으로 같다.** 집합을 100번 새로 만들었으니 딱 그만큼 배수가 붙는 것이다. 집합을 쓰긴 썼는데 이득이 통째로 날아갔다.

같은 실수의 변종이 `if x in list(d.keys())` 다. `d.keys()` 자체는 $O(1)$ 조회를 지원하는데 `list()` 로 감싸는 순간 선형 훑기가 된다. **`in` 앞에 함수 호출이 붙어 있으면 일단 의심해라.**
:::

::: warn 역인덱스를 만들면 중복은 마지막 것만 남는다
"값 → 위치" 딕셔너리는 자주 쓰는 전처리다.

```pyrepl
>>> seats = ["A3", "B1", "A3", "C7"]
>>> {s: i for i, s in enumerate(seats)}
{'A3': 2, 'B1': 1, 'C7': 3}
```

`A3` 의 위치가 **2로 덮어써졌다.** 0번 자리를 원했다면 이미 틀렸고, 예외도 안 난다. 요구사항에 맞춰 셋 중 하나를 골라라.

- 마지막 위치 → 위 컴프리헨션 그대로
- 첫 위치 → `for i, s in enumerate(seats): first.setdefault(s, i)`
- 전부 → `defaultdict(list)` 에 `append`
:::

## 딕셔너리를 쓰지 않는 것이 맞을 때

무기를 배우면 전부 못으로 보인다. 두 경우에는 꺼내지 마라.

::: perf 키가 0부터 n-1 까지의 정수라면 리스트가 낫다
20만 개 원소를 한 번씩 증가시키는 데 걸린 시간과, 컨테이너 자체가 쓰는 메모리다.

| 컨테이너 | 20만 회 갱신 | `sys.getsizeof` |
| --- | --- | --- |
| `list` (인덱스) | 6.6 ~ 8.6 ms | 1,600,056 바이트 |
| `dict` (정수 키) | 15.6 ~ 18.8 ms | 10,485,848 바이트 |

(Python 3.14.0rc2 / Linux 기준 실측. `getsizeof` 는 컨테이너 자체만 재고 안에 든 객체는 빼고 센다. 절대값은 기기마다 다르지만 자릿수 차이는 어디서나 같다.)

속도는 두 배 남짓이지만 **메모리가 여섯 배 넘게 차이 난다.** 격자 방문 표시([11.4](#/array-grid))나 알파벳 26칸 카운트처럼 **키의 범위가 처음부터 정해져 있으면 리스트를 써라.** 반대로 키가 문자열이거나, 범위가 넓은데 실제로 쓰이는 값은 드문드문하면 그때가 dict 자리다.
:::

두 번째. **검사할 때마다 `set(...)` 을 다시 만드는 것**은 원소가 몇 개든 손해다. 앞에서 본 `q in set(pool)` 과 같은 실수이고, 원소가 열 개뿐일 때도 그렇다 — 열 개짜리 튜플을 그냥 훑으면 169 ns, `x in set(seq)` 로 매번 변환하면 220 ns다. 변환 비용이 훑는 비용보다 크다.

**반대로 상대가 고정된 상수 몇 개라면 집합 리터럴이 낫다.** `set` 을 피할 이유가 없다.

```python
x in ("A", "B", "C")   # ❌ 미스면 세 번 비교한다
x in {"A", "B", "C"}   # ✅ 상수 폴딩으로 만드는 비용이 0이다
```

집합 리터럴의 원소가 전부 상수면 CPython이 컴파일 시점에 **`frozenset` 상수 하나로 접어 넣는다.** `dis.dis(lambda x: x in {"A","B","C"})` 를 찍어 보면 `LOAD_CONST 1 (frozenset(...))` 하나뿐이고 `co_consts` 에 그 `frozenset` 이 들어 있다 — 런타임에 집합을 만드는 코드가 아예 없다. 그래서 조회 시간이 찾는 값의 위치와 무관하게 일정하다. 2백만 회 반복의 회당 시간으로:

| 표현 | `x="A"` (첫 원소) | `x="C"` (마지막) | `x="Z"` (미스) |
| --- | --- | --- | --- |
| `x in ("A", "B", "C")` | 16.9 ns | 47.1 ns | 62.2 ns |
| `x in {"A", "B", "C"}` | 19.8 ns | 19.8 ns | 19.2 ns |

(Python 3.14.0rc2 / Linux 기준 실측, 5회 중 최소값.)

튜플이 이기는 경우는 **찾는 값이 첫 원소일 때 하나뿐**이고 그 차이는 3 ns다. 미스일 때는 튜플이 3배 느리다. 원소가 서너 개면 어느 쪽이든 나노초 단위라 실전에서 갈릴 일이 없지만, 굳이 고른다면 **집합 리터럴이 기본값이다.** 피해야 하는 것은 리터럴이 아니라 `set(변수)` 호출이다.

## 종합 — 한 문제에서 네 번의 키 결정

지금까지의 판단을 한 문제에 몰아넣었다. 코드를 읽기 전에 **주석의 결정만 먼저 읽고 각각을 스스로 정해 봐라.**

```python title="도서 대출 로그 정산"
from collections import Counter, defaultdict

logs = [
    "2026-03-02,kim,PY-101",
    "2026-03-02,kim,PY-101",      # 단말이 두 번 전송한 같은 기록
    "2026-03-11,lee,ML-204",
    "2026-04-01,kim,ML-204",
    "2026-04-02,park,PY-101",
    "2026-04-02,lee,RO-330",
]
catalog = {"PY-101", "ML-204", "RO-330", "DB-150"}

# ① 중복 제거 — 키는 "줄 전체". 원본 순서를 지켜야 하므로 set 이 아니라 dict.
rows = [line.split(",") for line in dict.fromkeys(logs)]

# ② 월별 건수 — 키는 "날짜의 앞 7글자". 데이터에 없는 필드를 만들어 냈다.
by_month = Counter(date[:7] for date, _, _ in rows)

# ③ 회원별 대출 도서 — 값이 set 이라 같은 책을 두 번 빌려도 한 번으로 접힌다.
by_member = defaultdict(set)
for _, member, book in rows:
    by_member[member].add(book)

# ④ 두 컬렉션 비교 — 한 번도 안 나간 책.
borrowed = set().union(*by_member.values())
never = catalog - borrowed

print(by_month)
print({m: sorted(b) for m, b in sorted(by_member.items())})
print(sorted(never))
print(sorted(by_member["kim"] & by_member["lee"]))
print(by_member["kim"].isdisjoint(by_member["park"]))
```

명시적인 `for` 문은 **하나뿐**이다. 나머지는 전부 키 결정이 코드로 굳은 것이다. ②에서 원본에 없던 "월"이라는 필드를 만들어 낸 것, ③에서 값의 그릇을 `set` 으로 고른 것 — 이 두 결정이 조건문 여러 개를 통째로 지웠다.

::: cote 시험장에서의 순서
1. **입력을 받자마자 조회용 집합을 만들어 둔다.** "이미 나온 적 있는가"를 한 번이라도 물으면 필요하다.
2. **중간에 `list.index()` 나 `list.remove()` 가 등장하면 멈춰라.** 둘 다 선형 훑기다. 위치가 필요하면 역인덱스 딕셔너리를 만들어라.
3. **출력 직전에 `sorted()`.** 집합과 딕셔너리를 그대로 찍지 마라.
4. 정규화 키를 만들었으면 **"같아야 하는 두 입력"을 손으로 넣어 확인하고 넘어가라.**

:::

## 요약

- 던질 질문은 하나다 — **"무엇이 같으면 같은 것으로 볼 것인가?"** 그 답이 키다.
- **키가 정해지면 값의 모양이 자료구조를 확정한다.** 개수면 `Counter`, 목록이면 `defaultdict(list)`, 중복을 접으려면 `defaultdict(set)`, 존재만 물으면 `set`.
- **키는 데이터에 있는 필드일 필요가 없다.** `"".join(sorted(w))`, `date[:7]`, 약분한 `(dx, dy)` 처럼 계산해서 만든 **정규화 키**가 이중 루프를 지운다. 정규화가 한 군데라도 빠지면 예외 없이 틀린다.
- **답이 "어느 것"이면 `set`, "몇 개"면 `Counter`.** 수량이 있는 문제에 집합 연산을 쓰면 개수가 조용히 사라진다.
- 중복 제거는 **출력 순서 조건부터 확인**한다. 순서를 지켜야 하면 `set` 이 아니라 `dict.fromkeys`.
- **`in` 이 $O(1)$ 이라는 사실은 코드를 줄이는 게 아니라 접근을 바꾼다.** "이미 지나갔는가", "구간의 시작점인가"를 공짜로 물을 수 있으면 $O(n^2)$ 이 $O(n)$ 이 된다.
- 키가 0부터 n-1 까지의 **정수면 리스트**를 써라. dict 는 메모리를 여섯 배 넘게 쓴다.

::: quiz 실습 과제 — 읽지 말고 짜라
전부 코드를 짜는 과제다. **각 문제를 시작하기 전에 "키가 무엇인가"를 한 문장으로 먼저 적어라.** 그게 안 나오면 아직 문제를 안 읽은 것이다.

1. **전화번호 정규화 그룹핑.** 표기가 제각각인 번호 목록을 받아, **숫자만 남겼을 때 같은 번호**끼리 묶어 반환하라. 두 개 이상 묶인 그룹만 결과에 넣는다.

   ```python
   nums = ["010-1234-5678", "01012345678", "010 9999 0000", "0109999 0000", "02-777-1111"]
   # {'01012345678': ['010-1234-5678', '01012345678'],
   #  '01099990000': ['010 9999 0000', '0109999 0000']}
   ```

2. **재고 대조.** 필요 부품 목록과 창고 보유 목록을 받아, **모자란 품목과 그 수량**을 딕셔너리로 반환하라. 남는 품목은 결과에 넣지 마라.

   ```python
   shortage(["볼트", "볼트", "너트", "와셔"], ["볼트", "너트", "너트"])  # {'볼트': 1, '와셔': 1}
   shortage(["볼트"], ["볼트", "볼트"])                                  # {}
   ```

3. **연속 좌석 확보.** 비어 있는 좌석 번호 목록과 인원수 `k` 를 받아, **연속된 `k` 자리를 잡을 수 있는지** 불리언으로 반환하라. 정렬을 쓰지 말고 풀어라.

   ```python
   has_run([3, 1, 2, 9, 10], 3)   # True
   has_run([3, 1, 2, 9, 10], 4)   # False
   has_run([], 1)                 # False
   ```

4. **부분 키 중복 제거.** `(회원, 좌석, 시각)` 기록 목록에서 **`(회원, 좌석)` 이 같으면 중복**으로 보고 하나만 남겨라. 두 버전을 각각 만들어라 — 첫 기록을 남기는 것과 마지막 기록을 남기는 것. 마지막 버전이 훨씬 짧아져야 정상이다.

   ```python
   rows = [("kim", "A3", "09:00"), ("kim", "A3", "09:01"), ("lee", "B1", "09:02")]
   # 첫 기록:     [('kim', 'A3', '09:00'), ('lee', 'B1', '09:02')]
   # 마지막 기록: [('kim', 'A3', '09:01'), ('lee', 'B1', '09:02')]
   ```

5. **월별 최다 이용자.** `(날짜, 회원)` 로그를 받아 **달마다 가장 많이 이용한 회원과 그 횟수**를 반환하라. 중첩 자료구조를 쓰되 반환값은 평평한 딕셔너리여야 한다. 동점일 때 어떤 회원이 나오는지 직접 확인하고, 그 동작이 어디서 정해지는지 설명하라.

   ```python
   logs = [("2026-03-02", "kim"), ("2026-03-09", "kim"),
           ("2026-03-11", "lee"), ("2026-04-01", "park")]
   # {'2026-03': ('kim', 2), '2026-04': ('park', 1)}
   ```

6. **직접 측정.** 3번 문제의 입력을 좌석 20만 개로 키우고, `set` 대신 `list` 로 같은 코드를 돌려 시간을 재라. 몇 자릿수 차이가 나는가. 그리고 좌석 번호가 0부터 연속이라면 무엇으로 바꾸는 게 맞는가.
:::
